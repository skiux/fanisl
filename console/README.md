# fanisl console

资产台。与 `frontend/`（知识引擎）同源共存，挂在 `/console/` 路径前缀下——
会话 cookie 因此不必跨站。

## 当前状态

后端已接（`GET /portfolio` · `/orders` · `/ledger`，见
`backend/src/analyzer/binance/README.md`）。全站需要登录，未登录只渲染登录页。

`src/api/types.ts` 仍是前后端的契约锚点，字段按 Binance 实际接口对齐：

| 契约字段 | 数据来源 |
|---|---|
| `wallets` | `GET /sapi/v1/asset/wallet/balance` 六个钱包的分布 |
| `spot` | `POST /sapi/v3/asset/getUserAsset` 四种锁定态 |
| `futures` | `GET /fapi/v2/account` + `/fapi/v1/accountConfig` |
| `futures[].liq_distance` | `positionRisk` 给了强平价才有；**给不出就是 null，不拿杠杆倒推** |
| `earn` | `GET /sapi/v1/simple-earn/{flexible,locked}/position` |
| `margin` | `GET /sapi/v1/margin/account` |
| `income` | `GET /fapi/v1/income`（资金费 / 已实现 / 手续费） |
| `transfers` | `GET /sapi/v1/capital/{deposit/hisrec,withdraw/history}` |
| `pnl` | 现货成交重放 + 合约 `positionRisk` / `income`（**不用日快照**，见下） |

**mock 层没有删掉**，它是评审降级态的唯一实用手段——451、限流、Key 失效这些状态
没法靠等来复现，而它们恰恰是这三页设计上最花心思的部分。数据来源默认 `实时`，
mock 场景**只在开发构建里可选**（生产留着这个开关，迟早有人把它停在"数据陈旧"上，
然后以为自己的账户真的陈旧了）。

## 登录

```
App → AuthGate → 三个页面
```

没登录就只渲染登录页，资产台一行都不挂载——与后端那道中间件同一个方向，**默认关**。
做成"渲染应用再各处判断"的话，三个页面各自处理未登录，漏一个就是一屏报错。

| 文件 | 职责 |
|---|---|
| `api/http.ts` | fetch 包装：`credentials: 'include'` · 非 JSON 视为错误 · 401 分流 |
| `api/session.ts` | 会话 store + 登录/退出/改口令 + 管理员接口 |
| `features/auth/AuthGate.tsx` | 闸门 |
| — | 登录页在仓库根的 `shared/login/`，**与知识引擎共用一份** |
| `features/auth/AccountPage.tsx` | 自己的账号（`#/account`）：改口令、看/撤销会话 |
| `features/auth/AdminPage.tsx` | 用户管理（`#/admin`，仅管理员，前后端都拦） |
| `lib/router.ts` | 两级 hash 路由 + `canView(页, 角色)` |
| `index.html` 里的引导脚本 | 首帧之前定下深浅色 |

几处不是随手定的：

- **`credentials: 'include'`**：线上同源浏览器默认带 cookie，本机开发跨端口
  （5175→8000）默认的 `same-origin` 会把它丢掉——症状是"登录成功了但每个请求还是 401"。
- **非 JSON 响应直说是 nginx 的事**：少配一个路径前缀时，API 请求会落到 SPA 兜底返回
  index.html，直接 `JSON.parse` 只会报一句语法错，指不到真正的原因。
- **全局 401 排除 `/auth/*`**：口令输错也是 401，那是表单内的错误；不排除的话输错一次
  就触发全局登出，登录页把自己重置一遍。
- **图表用 recharts，不自己画。** 这是唯一一个非 Radix 的重量级依赖（约 +96KB gzip，
  实测 153 → 250）。手搓 SVG 画得出静态的环，画不出指哪块哪块凸出来、跟手的提示框、
  移开之后干净地收回去——而这些在十几个标的的时候比配色重要得多。
  只有它的**入场动画**要关掉，理由见「风险控制」那节。
- **交互原语用 Radix，不自己写。** 这个项目一度让同一件事长出四套实现：资产页的分节
  导航（90 行，自己量标签宽度画指示条、自己接 ResizeObserver 与 `document.fonts.ready`
  重新量、自己写方向键）、流水页的区间切换、委托页的账户筛选、场景切换器——长相各不
  相同，键盘行为也各不相同。账号菜单更直接：`absolute right-0` 没有碰撞检测，窄屏下
  报头折行之后面板会飘到屏幕外。
  现在"选一个"统一走 `components/controls.tsx` 的 `SegmentedControl`（Radix ToggleGroup），
  弹出面板走 `DropdownMenu`（`collisionPadding` 负责翻转贴边）。视觉仍然是我们自己的；
  交给库的是键盘漫游、`aria-*`、焦点归位、碰撞检测——这些自己写从来不是设计取舍，
  只是把无障碍写错的机会多来一次。
  **选项多到摊不开就换 `components/Select.tsx`**（Radix Select）：分段下划线要求
  一眼看全，委托页的交易对可能有几十个。首字母跳转（打 `SOL` 直接跳到 SOLUSDT）
  是 Radix 自带的，所以没做搜索框。
- **原生表单控件顶不住的地方就别硬用。** 这条原先写的是"日期选择用原生
  `<input type="date">`，自己写日历弹层是最典型的造轮子"。日期与交易对后来都换掉了，
  换的理由是同一个：**原生弹出层由系统画，进不了这套纸面语言，也塞不进第二层信息。**
  日期要的是"起止两个日子 + iOS 那种滚筒"，原生 date 只能选一天；交易对要的是
  "哪些正挂着单"，`<option>` 里放不下。代价是键盘与无障碍得自己盯——所以两个都
  建在 Radix 上（`RangePicker` 用 Popover、`Select` 用 Select），我们只画皮。
- **界面上只有数字，没有小字。** 这条来回改了五轮才定下来，规则是：
  - **解释数字怎么算的删掉**——"现货按成本 · 合约按标记价"、"没有统一接口，合并而来"。
    那是口径，属于本文件和 `backend/src/analyzer/binance/README.md`。
  - **把数字翻成一句判断的也删掉**——"安全"、"很近"、"不可用"。它读着像信息，
    其实是把 `4.5%` 换个说法再说一遍，而且只有三格里的一格常年有这句，
    整条摘要条就为它高出一行、还错了位。这类判断改用**颜色**：数字自己转金转红
    （`StripCell.tone`），一个像素都不多占。
  - **影响可信度的警告留下**——"2.48 成本不明"、报头的"3 项取不到"。它不是解释，
    是"下面这个数不全"。这类提示按**状态**出现，不按角色藏：全绿时不出现。
    **但同一句只说一处**：流水页摘要条原本也数了一遍取不到的来源，
    报头拿同一个 `sources` 已经在说了，说两遍只会让人以为是两回事。

  同理删掉的还有流水页的「取数窗口」（端点清单）与「取数成本」（权重、调用次数），
  以及三个页面的页脚口径。角色判断只剩三处真需要的：知识库入口、重新取数按钮、
  凭据排查清单——那三样成员做不了也不该看。

- **要核对数字就点开，而且两项都能再拆一层。** 摘要条上只有「今日盈亏」可点，
  开一张两级的构成表：

  ```
  现货涨跌                 +$127.30
    BNB  6.212 · $669.87 → $682.15 · +1.83%    +$76.28
    …                                          （按金额大小排，算不出来的排最后）
  当日结算                 +$141.00
    已实现盈亏                                +$131.13
    资金费 / 手续费 / 返佣                        …
  合计                     +$268.30
  ```

  分项之和精确等于自己那一行——两级数字上下摆着，差一分就看得出来
  （后端 `today.settled_parts` 与 `settled_usd` 同源，见 api.md）。
  **印出来是 `$0.00` 的那几行不列**（两级都是这条）：灰尘币一天动不了一分钱，
  十几行 `+$0.00` 会把真正动了的那几个挤下去；"今天没有资金费"也不需要单独占一行。
  判的是**进位之后**是不是零（`|v| < 0.005`），不是 `=== 0`——0.004 印出来一样是
  `+$0.00`。`null` 不在此列：取不到和是 0 是两回事，那一行留着写「取不到」。
  上一版逐币表浮在最底下、和「现货涨跌」那一行隔着「合计」，而合约那半边干脆
  没有下一层，只有一个 −$12.30，看不出是资金费还是手续费。
  另外两格不可点——合约未实现是 `positionRisk` 直接给的一个数，拆不出下一层。
  抽屉里**只有数字没有说明**——回答的是"怎么凑出来的"（数据），不是"取自哪个接口"（构造）。

- **净值走势图删了，换成每日盈亏日历。** 那条线画的是日快照拼出来的净值，而快照只有
  现货 / 全仓杠杆 / U 本位三个钱包——把钱从现货挪进理财，线就往下掉一截，看着像亏了。
  一条会因为划转而骗人的曲线不如不要。日历只认成交与结算，划转动不了它。
  日历按**月**浏览（‹ 2026 年 9 月 ›，六行固定高度），区间预设（7/30/90/自定义）
  另管统计范围：区间外的日子照常画出来但压暗、不计入合计。这两件事混成一个的话，
  就会渲染出"8 月从 5 号开始"那种半截月份。自定义走独立的滚轮选择器，见下。

- **不做 K 线。** K 线要开高低收四个值，"这天赚了多少"只有一个数，照 K 线画就得编三个。
  热力图也不是没用，但那是**年视图**的做法；月视图就该是规规矩矩的日历
  （TradeZella / Tradervue / TradesViz 三家都是这么做的）。

- **主题在首帧之前定，不在组件里定**。切换器住在报头里，而登录页没有报头——
  把初值写在 `<html class>` 上的话，选了浅色的人在登录页永远看到深色，
  其他页面则会先画一帧深色再跳成浅色。判断放在 `index.html` 的内联脚本里，
  `ThemeToggle` 只负责写。两处都判断一次的写法迟早会不一致。
- **成员进 `#/admin` 直接退回资产页**（`canView`，用 `replaceState` 不留历史）。
  后端会 403，但让人先看见"用户管理"的标题再看见一屏错误，是把权限问题讲成了故障；
  而"重新取数"这种按钮在权限问题上按多少次都不会好。
- **管理页的行内操作是文字不是图标**。原先是 13px 的图标，其中"改角色"用的还是一个
  循环箭头——跟报头上"重新取数"同一个符号，指的却是"把成员升成管理员"。
  重置口令走行内的口令输入框，不用 `window.prompt`（原生框里口令是明文）。
- **自己那一行不给任何管理动作**，只留一条去「账号」页的链接。停用和删除后端本来就拒绝，
  降级后端过去不拒绝——手一抖就把自己踢出管理面，且只能求另一个管理员捞回来。
- **管理页不复制后端的判定规则**（最后一个在岗管理员不能停用/降级/删除、不能删自己）。
  前端复制一遍必然与后端漂移，而漂移方向通常是前端更松。这里只把 409 的原话显示出来。
- **账号页与用户管理页的纸张按内容收**，不钉在视口高度——那两页内容不多，钉住只会在
  下面留一大片空白。数据页要钉住是另一回事：那是为了让切换分节时页面高度波动为 0。
- **「没有数据」与「为什么没有」分开判**。原来写的是"每个来源都 unauthorized"，
  而 `prices` 是公开端点、没有 key 也照常返回，于是这个条件再也不成立——
  没配 key 会被误报成"账户里还没有资产"，屏幕上还留着一句"前往 Binance"，方向指反了。

## 命令

```bash
npm install
npm run dev          # http://127.0.0.1:5175/console/
npm test             # vitest：http 层、会话、路由与权限
npm run typecheck
npm run lint         # 见下，别跳过
npm run build
```

**`npx tsc --noEmit` 什么都不查。** 这份 tsconfig 是 solution 式的（只有
`references`，没有自己的 `files`/`include`），不带 `-b` 时 tsc 找不到任何输入文件，
安安静静退出 0。要查类型只有 `npm run typecheck`（`tsc -b`）。
2026-09-05 踩过：拿 `--noEmit` 连着"验"了四遍全绿，换成 `-b` 一次冒出四个错。

**`npm run lint` 不是可选的。** 这个项目原先没有 lint，代价是实打实的：
`RealizedDays` 把空数组的守卫写在几个 `useMemo` 之后——hook 先跑、守卫永远轮不到，
合约域名 451 时 `pnl` 为空，整页白屏（两个场景六个页面全白）。TypeScript 查不出来，
人眼也看不住，只有 `react-hooks/rules-of-hooks` 能拦。加上 lint 的当天它就又抓到
一处同类（`StatementPage` 的详情抽屉 `useState` 写在了两个提前 return 之后）。

规则**只开正确性两条**，没开整套 recommended——新版插件里还带着一批 React Compiler
的风格规则（effect 里不许 setState 之类），要满足它们得把取数逻辑整个重写，
那是另一件事。

## 降级态怎么验

`?scenario=` 切换十种 mock 状态（`src/api/client.ts` 的 `SCENARIOS`）。
**每次改完至少扫一遍全部场景 × 全部页面**，只测 `ok` 是不够的——上面那次白屏就是
`fapi_blocked` 与 `no_history` 两个场景独有，而它们在 `ok` 下永远不出现。

```
ok · stale · fapi_blocked · all_blocked · no_history · unauthorized · empty · loading · down
```

扫的时候看四样：控制台报错、页面几乎空白、横向溢出、渲染出 `NaN` / `undefined`。

**别拿缩略图下结论。** 截图缩到 0.5 会把细笔画采样掉，看着像整块"发灰"、
下划线像落在隔壁标签上——都是假象。要判断长相就看全分辨率，要判断状态就读
`data-state` / `aria-*`，别靠眼睛在缩略图上猜。

**后端起不来时也能验前端**：`runtime.py` 在模块级就打开知识库连接池，它指向
生产隧道，隧道断了资产台跟着起不来（尽管它从不碰知识库）。这时候起一个只回
`/auth/me` 的桩，再用 `VITE_API_BASE` 指过去，页面数据照样走 mock 场景。

mock 层**不能删**：451、限流、Key 失效这些状态没法靠等来复现，而它们恰恰是这三页
设计上最花心思的部分。场景开关**只在开发构建里可选**（`import.meta.env.DEV`）——
生产留着它，迟早有人把它停在"数据陈旧"上，然后以为自己的账户真的陈旧了。

## 形态

报头 → 常驻摘要条 → 分节导航 → 明细区。**没有页脚**：原先那条写着口径与来源计数，
两样都是构造，删了。

```
┌──────────────────────────────────────────────────┐
│ 资产报表                      13:09 UTC · 重新取数 │
├──────────────────────────────────────────────────┤
│ 净值        今日盈亏    合约未实现   合约保证金率   │
│ $48,626.33  +$127.30    +$810.21        4.5%     │
├──────────────────────────────────────────────────┤
│ 总览    持仓    合约    风险控制                   │  ← 下划线滑动
├──────────────────────────────────────────────────┤
│            选中的那一节（整幅宽度）                 │
│            宽屏时区域内部滚动                       │
└──────────────────────────────────────────────────┘
```

- **四个分节**，一路从六个减到三个又拆回四个。「理财」只有 3 项、「风险」只有 2 个读数，各自
  填不满一个视图（实测填充率 26% / 36%）——那是分节分错了，不是内容不够。
  最后去掉的是「盈亏」：它只有日历、合约收支、充提三块，而**日历在总览也有一份**，
  同一张表在两个分节里各印一遍；另外两块本来就和日历同一个问题（这段时间赚了多少），
  合到总览反而连贯——上面逐天，下面这 90 天按项拆开。
  最后一次动是把「合约与风险」拆成「合约」与「风险控制」：那一节既列仓位与保证金
  （**现在是什么样**），又摆着几个风险读数（**会怎样**），两件事挤在一起谁也没说透。
  取不到数据的那一节标灰但仍可点（`muted`），不必点进去才发现。
- **模块标题上的箭头只在"点开有别的东西"时才给。** 总览的「每日盈亏」原先点标题
  跳到「盈亏」页，而那个动作和上面分节标签里的「盈亏」一模一样——**同一个去处
  摆了两个入口**，多出来的那个只会让人以为点进去能看到别的。箭头去掉，日历留着：
  总览的时间维度就靠它。「资产分布」「风险仪表」的箭头照旧，它们点进去是明细页，
  内容确实不一样。
- **导航横向、小字、无底框**，选中态是颜色 + 一条走 `transform` 的下划线。
- **摘要与导航分开**：导航只管导航，四个关键数字另立一条常驻条。
  （曾把两件事塞进一根侧栏，结果既不像导航也不像摘要，还吃掉 224px 宽度。）
  三个数据页共用 `components/Strip.tsx`，对齐规则见下节——**那里改之前先读它**。
- 桌面把整张纸钉在视口内、明细区内部滚，**切换分节时页面高度波动为 0**；
  窄屏不钉（整页滚动），钉住只会让可视区更小。
- 降级看得见但**只说一处**：取不到的那个数字自己是 `—`，出问题的模块自己会说明，
  总览页另有一块「下面的数字不完整」逐个列出是哪个来源。报头不再重复计数。
- 视图状态进 hash（`#/overview` `#/holdings` `#/perp` `#/risk`），可直接链到某一节。
  `#/changes` 是删掉的那一节，落到它会退回 `overview`——那里就是同一份内容。

纸张与三种字体的身份沿用：标题 Newsreader（衬线），标签 Geist，数字 Geist Mono
（tabular）。浅色为主设计目标，深色是同一份报表在暗处的读法。

## 摘要条的对齐

`components/Strip.tsx`，资产 / 委托 / 流水共用。一个主数字（40px）加两到三个指标
（21px），横排。**这处几何改坏过四次**，写在这里免得第五次：

一排里字号不同的数字，同时想要三件事——

1. 标签落在同一条线上
2. 数字落在同一条线上
3. 每格里标签到数字的距离一样

拿**基线**当第 2 条的那条线，就必然要牺牲第 3 条：字号不同而基线相同，
意味着矮的那个整体下沉（下沉量 = 字号差 × 上伸部系数，40px 与 21px 之间约 20px），
这 20px 只能从它的标签底下挤出来，标签就飘了。反过来底对齐（`items-end`）保住 2、3，
断掉的是 1：有第三行的那格整块下移。四次改动就在这两个错之间来回换。

出路是**别拿基线当那条线**。`leading-none` 下顶对齐得到的是一条字身顶线，
实测 40px 的 `$48,626.33` 与 21px 的 `+$236.42`，墨迹顶只差 0.86px——
肉眼就是一条线。于是：

```
items-start（容器）+ mt-2（每格内部，两档共用）
```

三条同时成立，标签基线四格完全重合。**别再往里加 padding 去"对基线"。**

顺带两条同源的约束：

- **每格只有标签和数字两行，没有第三行。** 三格里只有一格常年有小注的话，
  那两个字既撑高整条又让这格跟邻居不齐。要提醒就用 `tone`。
- **窄屏用 `grid grid-cols-2`，不是 flex。** flex 下第二列的 x 取决于第一格数字
  有多长，`+$236.42` 变成 `+$1,236.42` 整列就挪一次。

量这类东西**不要用 `getBoundingClientRect`**：它给的是行盒，不是基线也不是墨迹。
要基线就用 `Range.getClientRects()` 的顶 + canvas `measureText` 的
`fontBoundingBoxAscent / 1000 × 字号`；要墨迹顶就再减 `actualBoundingBoxAscent`。
拿行盒或空 `inline-block` 探针量出来的数一次都没对过。

## 现货这一侧没有"相对成本"的任何数

未实现没有，已实现也没有——两者要的是同一段**补不齐的买入历史**：划转 / 理财派息 /
小额兑换进来的币在 `myTrades` 里没有痕迹，90 天以前的充值也查不回来。
卖得比重放看到的多时能被识破（那个币会标成成本不明），可**买得比看到的多、
卖得不多时无声出错**——报一个看不出错的数比不报更糟。

后端那套成本基础引擎（`Lot` / `replay` / `summarize`）连同 `spot_assets`、
`realized.spot_usd` 一起删了。现货只剩"每天涨跌了多少"。

## 合约收支：四行同一个窗口，条形才可比

旧的「盈亏构成」七行混着四种窗口：现货今日涨跌（1 天）、合约未实现（此刻）、
现货已实现（全历史）、合约已实现与资金费手续费（90 天）。条形是让人比较长短的，
而 `+$3,847`（90 天）旁边摆着 `+$127`（今天）比出来的东西没有意义。

现在只剩合约那四行，全部来自 `/fapi/v1/income`、同一个 90 天窗口，加得起来。
现货涨跌归日历（那里才有区间概念），合约未实现归摘要条（它是"此刻"）。

右边原先还有一块「成本」，写着毛利 / 成本 / 成本占毛利 / 日均资金费——全是同样
那四个数换个排法（毛利 − 成本 恰好等于左边的合计），同一屏说两遍，删了。

## 日历是每天真实的盈亏，不是成交结算

摘要条是 净值 / **今日盈亏** / **合约未实现** / 合约保证金率。

- **今日盈亏 = 日历最后一格**，不另算一遍。它由两项组成：现货持仓当天涨跌了多少，
  加上合约当天结算掉的。点开这两项各自还能再拆一层——逐币的涨跌、结算的分类。
- **日历每一天都有数。** 原先一格只算"那天结算掉的"，于是不成交的日子（包括每个
  周末）全是 0——那不是"这天没赚没亏"，是"这天没成交"。现货拿着不动也在涨跌。
- **合约未实现只有合约。** 现货那半边**不存在未实现这一项**：它是市值减加权平均
  成本，而那个成本要完整的买入历史，划转 / 派息 / 小额兑换进来的币在成交记录里
  没有痕迹，90 天以前的充值也查不回来。合约不一样，`unRealizedProfit` 是交易所
  按自己的开仓均价给的，拿来即用。
- **现货那边没有"已实现"可加**：卖出那笔的盈亏已经含在当天的市值变化里了。
  相对成本的那套数整个删了，见上一节。

算不出来的那天是 `null`，日历上留空——0 会被读成"这天没赚没亏"。
口径与回滚方式见 `backend/src/analyzer/binance/dailypnl.py`。

## 日历怎么画

- **周日起头**（日 一 二 三 四 五 六）。汉字本来就是单字，窄屏不用再缩写。
- **周末不压暗。** 币是 7×24 的，资金费周末照样结算、持仓周末照样涨跌，
  压暗等于说"这两天不太算数"。
- **每天一块独立的圆角色块，靠间距分隔而不是描边**——三十多个方框会把这一页
  压成一张表单。
- **深浅按金额大小**，下限 9%、上限 29%。见过的参考实现用同一个深浅，于是
  +0.17 和 +68.29 一样绿，白丢掉了"哪几天真的要紧"；抬高下限是为了让小额也看得见。
- **日期数字是这张表的索引**，用 ink 而不是灰字——原先 11px 的灰日期比金额还轻，
  翻月时要盯着找。今天那一格加一圈细环。
- **金额位数跟着量级走**（`compact`）：十以下两位小数、百以下一位、千以下取整、
  再往上压成 `1.2k`，最长五个字符。一律取整的话几毛钱的日子会印成 `+0`，
  看着像没赚。符号一律保留——红绿在色盲下分离度只有 ΔE 6.1，符号是第二重编码。

## 时区一律 UTC，并且标出来

日切按 **UTC**：日历的每一格、成交与结算的分桶，都是 Binance 的 UTC 结算日。
时刻（`clockTime`）也按 UTC 渲染——两套时区混着用的话，跨零点那几个小时里
报头的时刻与日历会指着不同的一天。

**报头那个时刻后面缀"UTC"两个字母。** 读的人在 UTC+8，屏幕上写 `13:09` 而墙上是
`21:09`，不标就会当成本地时间差出八小时。那两个字母是**数据的一部分**（这个时刻
按哪个时区读），不是说明文字——这跟本文档反复说的"口径不进界面"不冲突。

只标一次：流水页一屏九十行，每行后面挂一个 UTC 是噪声，所以 `clockTime` 自己
不缀时区，由报头那一行统一交代。

**"多久以前"用 `relativeTime`**，它和时区无关：过期横幅、最近登录、来源健康
（「1 分钟前」）都走这条。绝对时刻只用在需要排先后的地方——报头的截止时刻、
流水页逐行的时间。

前面也不写"截至"：一个时刻摆在报头上，本来就是"这些数字截到什么时候"。

## 同一件事只说一处

报头原先在「截至」旁边挂着「N 项取不到」/「数据已过期」，两句都删了——**同一件事
说三遍**：

- 取不到：那个数字本身就是 `—`，出问题的模块自己也会说（「合约数据本次没有取到」），
  总览页还有一整块「下面的数字不完整」逐个列出是哪个来源、各自多旧。
- 过期：页面顶上另有一条横幅，而且那条才说得清后果（"下面全部数字来自 4 小时前的
  快照，不是当前余额"）。

报头那个计数既指不到具体哪个数，普通用户也做不了任何事。

## 区间选择

`components/RangePicker.tsx`：上面两个日期（左起点右终点，点哪个下面就改哪个），
下面两列滚轮（左年月、右日）。

**滚轮是 iOS 那种滚筒**：中间一项正对，上下的逐渐变小变淡、绕 X 轴向后倒，顶底渐隐，
选中条横跨两列（不是每列一条）。第一版是一列平的文字加一块灰底，那不是同一个东西。

两样都交给浏览器，**一行动画 JS 都没有**：吸附与惯性用 `scroll-snap`，倾倒用
滚动驱动的关键帧（`animation-timeline: view()`，见 `index.css` 的 `.wheel`）——
每一项按自己在容器里的位置走同一条关键帧，0% 刚从底部进来、50% 正居中、
100% 从顶上出去。手写要在 scroll 事件里逐项改 transform 再自己接 rAF。
`@supports` 之外降级成一列平的文字，吸附与点选照常；`animation: … both` 在不支持
时会把每一项停在 0% 那一帧（透明），所以整段必须包在 `@supports` 里。
`prefers-reduced-motion` 下明确关掉滚筒——滚动驱动的动画不吃 `animation-duration`，
指望全局那条 `!important` 按住它是靠不住的。

三处踩过的坑，改之前先读：

- **「自定义」不能放进 `SegmentedControl`。** Radix 单选组点已选中项不触发
  `onValueChange`（那是"取消选中"），于是选过一次就再也打不开选择器。
  它是一个独立按钮，用 `segmentClass()` 保证长相一致。
- **滚轮对位必须在布局阶段做**（`useLayoutEffect`）。Popover 打开那一刻才挂载，
  用 `useEffect` 的话首帧容器还没布局，滚动请求落空——打开看到的是停在 0 的滚轮。
- **程序滚动一定要配解锁兜底。** 曾经把"点 7 月，字段变了而滚轮纹丝不动"诊断成
  "`scroll-snap: mandatory` 取消了平滑滚动"，为此退回瞬时跳、还把吸附临时摘掉——
  两条都是错的。实测的原因是**本项目的预览面板整个关掉了平滑滚动**（连页面主滚动
  容器都不动），于是 `scrollTo` 不产生滚动、`scrollend` 永远不来：只靠事件解锁的话
  `driving` 永久为真，之后用户自己滚也回读不出值；而摘掉的吸附同样因为事件不来
  再也装不回去。现在是 `glide()` 里一个 600ms 的兜底定时器解锁并强制就位，
  吸附一次都不动。

选中之后**按钮上直接写着区间**（`2026-07-15 — 2026-09-03`），不另起一行说明。

## 合约里的币也是现货持仓

持仓页多了一节「合约中的现货持仓」：合约与全仓杠杆钱包里躺着的非稳定币。
把 BNB 划进合约当保证金、抵手续费是常见做法，它们仍然是现货持仓，只是不在现货
钱包里。「现货持仓」那张表只读现货钱包，于是这些币在页面上凭空消失，看着就成了
"现货数据取不到"——**量一直都在**。盈亏那边一直是按跨钱包持有量算的。

## 风险阈值只有一份

`lib/risk.ts`。合约保证金率原先在同一屏上按三套标准判——风险仪表在 0.6 转红，
而它自己在 0.8 处画着"危险线"（条早在红线之前就红了），摘要条又是第三套；
数字还印了两种精度，`4.5%` 与 `4.46%`，看着像两个数。

规则：**判色、判语、仪表上那条标记线，三样取自同一组常数；同一个量全站同一档小数位。**
保证金率取 0.5 偏紧 / 0.8 危险（到 100% 就是强平，0.8 只剩两成缓冲，
也正是仪表本来画的那条线）。强平距离是另一把尺，别跟它混。

判语（"安全""偏紧"）只留在**风险仪表**里：那里有一条带颜色的进度条，
判语是这个颜色的说明，色觉障碍的人靠它读同一件事。摘要条没有条也没有图例，
判语在那里只是把 `4.5%` 换个说法再说一遍——所以摘要条只上色，不写字。

## 真实杠杆只指一个数

「合约与风险」的「多空敞口」里那格是 **名义敞口 / 保证金余额**。两个操作数都在同一
页上——分子是这块自己的读数（`$27,566.70`），分母是隔壁「保证金」的读数
（`$10,050.21`）——看得见也验得了。

它替掉了原先那格「最高杠杆」。那是**开仓上限的设置值**，每一行仓位自己已经写着
`3×`，扫一眼就有；摆进汇总里是把同一件事说两遍，而"这笔保证金实际扛着多少倍"
反倒没人给。

总览「风险仪表」底下还有一个 `0.57×`，分母不同（全账户净值），标签本来就写着
「名义敞口 / 净值」。原先它后面缀着"· 真实杠杆"，现在去掉了：**一个名字指着两个
不同的数，早晚有人拿它们对不上。**

## 列表排序

`components/controls.tsx` 的 `SortBy`。目前用在「合约仓位」上，接口是通用的。

- **每个排序键自带方向**（`SortKey.initial`）。金额、盈亏、杠杆是从大到小要紧，
  而「距强平」恰恰相反——离得最近的那个仓位才是要先看的。一律给 `desc` 的话，
  点「距强平」会把最安全的顶到最上面，正好把这个键的用处反过来。
- **再点一次翻方向**，当前键旁边有箭头指着方向。翻方向走 `onClick` 而不是
  `onValueChange`：Radix 单选组点已选中项算"取消选中"，回调收到的是空串
  （「自定义区间打不开」就是这条坑）。建在 `ToggleGroup` 上是为了键盘漫游与 `aria-*`。
- **取不到的一律排最后，跟方向无关**（`compareBy`）。不这么写的话，按「距强平」
  升序会把一堆没有强平价的仓位顶到最前面，而那一列恰恰是用来找最危险的那个的。
- **默认按名义从大到小**，不照抄接口给的顺序——那是账户内部的次序，和"哪个仓位
  要紧"无关。
- 只有一行时不画排序条：没有第二行可以换位置。

## 历史默认就是"我的历史"

委托页的「历史」不带交易对时显示**全部**：后端把候选里的每个交易对都问一遍再合并，
表里每行标出是谁的。选定一个才收窄到那一个。

`allOrders` / `myTrades` 的 symbol 必填是**接口**的限制，不该变成产品的形状——
上一版后端取候选的第一个，于是这一节永远在讲某个标的，而标题写着「委托历史」。

合并之后随之而来的三件事：

- **窗口取交集**：现货单次 24 小时 / 无回溯上限，合约 168 小时 / 90 天，合起来
  报 24 小时 + 90 天。
- **一个交易对挂了不清空整页**：取到的那部分照常显示，模块的小注改成
  「不含取不到的交易对」（同「挂单」页那条「不含取不到的账户」）。全都没取到才换成
  「历史查询不可用」那一屏。451 常常只打 fapi，现货那半边还在。
- **默认只摊开 7 天，两张表各自封顶。** 改成"不选交易对就是全部"之后，这一页一次要
  摊开十几个交易对的九十天历史——真账户几百上千条，页面被拉成几千像素高，翻到底下
  那张「成交明细」要滚很久。区间控件在「查询范围」里（7 / 30 / 90 天），管的是
  **这一屏摊开多少**；它和旁边的「取数范围」是两件事，后者是后端一次取回来多少
  （按 orderId 翻页，取的时候没法只要最近几天）。两张表另外各自 `max-h` + 内滚，
  表头留在框外——这样不管多少条，页面高度都是有界的。
- **手续费只能按 USD 求和**（`Fill.commission_usd`）。`commission` 的单位是
  `commission_asset`，现货常用 BNB 抵扣、合约结在 USDT；合并之后必然跨币种，
  直接相加等于把 0.0008 个 BNB 当成 0.0008 美元。逐行那一列显示的是**币的数量**，
  所以用 `amount` 而不是 `money`——按金额格式印出来是 `0.00`，看着像没收费。

## 交易对选择器

`components/Select.tsx`（Radix Select），委托页「查询范围」用。原生 `<select>` 换掉
的理由不是配色：`<option>` 里塞不进第二层信息，而这份候选最需要说的恰恰是
**哪几个正挂着单**——`allOrders` 必须传 symbol，候选本身是后端从"有挂单 + 有持仓 +
现货余额能配出的对"推出来的（做不到全量），要查的多半就是挂着单的那几个。

- 每一项是 `BNB` + 灰色 `USDT`，行尾 `×4` 是该交易对当前的挂单条数（没有就不写）。
- 按计价币分组，**只有一组时不画分组标题**——整份候选都是 USDT 计价很常见，
  那行「USDT」什么也没区分。
- 拆对用 `lib/format.ts` 的 `splitPair`，**不是 `baseOf`**。`baseOf` 的结果还被当成
  "美元报价的键"用（`api/prices.ts` 拿它查 `PRICE`），只认 USDT 是对的：ETHBTC 也
  拆成 ETH 的话，那边会拿 ETH 的美元价当成 ETH/BTC 的价格，静悄悄地错。
  两个函数看着像，但不能互相替换，有测试钉着。

## 现金和持仓是两回事

"哪些资产算现金"**由后端给**（`snapshot.stable_assets`），前端不再维护名单——这件事
原先在四个地方各写一份、四份还不一样，理由与后果见
`backend/src/analyzer/binance/README.md`。

界面上因此多了两处：

- **持仓页的「现金」**。它不是「理财持仓」的缩略版，是另一刀：那张表按产品列理财，
  这里按"钱在哪"横切整个账户。同一笔 USDT 可以同时躺在现货、在理财里生息、
  在合约钱包里当保证金，而这三处原先分在三张表上——"我一共有多少可动用的钱、
  其中多少已经压在保证金上"没人回答。逐行带年化，稳定币理财的收益也就有地方看了。
- **`lib/holdings.ts` 的 `exposures`**：按标的把现货类持有与永续名义**合并**。
  这是原先谁都没做的一步——NVDA 的现货在一张表、NVDA 的永续在另一张表，
  相加才是价格动一下账户真实的暴露。空头带负号，多空对锁时净敞口接近零；
  「最大单一敞口」也改用它，原先会把对锁的两条腿里大的那个报成集中持仓。

## 风险控制：能扛多少，不是现在多少

`RiskControl.tsx` + `lib/stress.ts`。总览的「风险仪表」是三个**此刻**的读数，
合约页是**逐个仓位**的距强平，两处都回答不了"再跌多少我出局"——
逐个仓位各看各的距离，而全仓是共用一份保证金的，多个仓位一起亏才是真实情形，
分开看会系统性地低估。

四块，从"现在怎样"走到"还能扛多少"：**临界跌幅**（一起跌多少开始强平，以及补上
现货现金之后是多少）、**敞口分布**、**压力测试**（选跌幅看净值 / 保证金率 /
可用余额 / 谁被强平）、**现金缓冲**（还能补多少）。

三个想清楚了才写下来的地方：

- **饼图和横条并排，因为它们回答的不是同一个问题。**
  饼只画**多头**：现货 + 合约多头名义，答"钱压在哪几个东西上"。
  横条画**净敞口**：空头带负号抵掉同一标的的现货，答"价格动一下账户真实暴露多少"。
  **饼画不了负数**，这是它单独用不够的原因，也是横条留着的原因——多空对锁的标的
  在饼里看着仍然很大，在横条上两边都短。横条零点放中间，多头往右、空头往左。
  两处的合计因此不同（模块抬头是净敞口，饼旁边另写一行「多头合计」），
  不写出来会以为饼是照抬头那个数分的。
- **画图交给 recharts，不手搓 SVG。** 手搓那版画得出环，画不出指哪块哪块凸出来、
  跟手的提示框、以及移开之后干净地收回去。我们只管颜色、块里写什么、圈心写什么。
- **标签写进块里，不给图例。** 代码在上、占比居中放大、金额在下。摆在环外要配引导线，
  摆在下面要低头对号；而只给百分比的话，"27.8% 到底是多少钱"还得回到右边的横条上找。
  门槛 6%：标签落在弧中点，两个 6% 的块中点相距约 55px，而一行 `$8,662` 就有 44px，
  再小就叠字。写不下的（这里 0.4% 的「其他」）在下面补一行。
- **合计写在圈中间，不带标题。** 甜甜圈那个洞就是给它留的。
- **入场动画关掉 recharts 的，改用 CSS。** recharts 走 `requestAnimationFrame`
  （react-smooth），而 **rAF 在页面不可见时不发**：标签页在后台加载，扇区角度永远停在
  0，整张图一块都不画——不是"没动画"，是空白。CSS 那条只写 `from`、不写
  `animation-fill-mode`，静止态就是最终态，动画跑不起来也只是没动效。
  这和滚轮那次是同一条教训：**别让动画成为"画不画得出来"的前提。**
  （这个坑是在预览面板里撞上的——它的 `document.hidden` 恒为真，所以带动画的版本
  在这里根本验不了；要看动效只能开真浏览器。）
- **色只负责把相邻两块分开，"哪块大"交给块里那个百分比。**
  第一版按名次把色相从 192° 摊到 320°，画出来是一圈深浅不一的蓝——
  27.8 / 26.6 / 24.1 / 21.1 四块角度本来就几乎一样，颜色又只差二三十度，等于没画。
  根子是**能用的色相不够**：绿(155°)、红(30°)、黄铜(85°)已被盈亏与充提占死。
  现在是顺序色阶（`--pie-1..6`），明度与色相一起动。**深浅两套各写一遍**，
  因为方向要反过来：浅色纸上"墨重"是深，深色纸上是亮。整条又压在离 `--ink` 足够远的
  一段里，块里的字才能一律用 `--ink`，不必按名次换字色。
  「其他」用分隔线的灰：它是余数，不该比谁都显眼（第一版它是最艳的那块）。
- 占比不到 1% 的并进「其他」：只按名次封顶的话，0.2% 的 ETH 会自己占一块，
  而它比旁边那个「其他」还小。
- **全仓仓位不报"触及强平价"。** 交易所给的 `liquidationPrice` 是"别的都不动、
  只有这个仓位的价格变"算出来的，而压力测试恰恰是所有标的一起跌，那个价在这种
  情形下不成立。全仓的判据是账户保证金率到 1（`breakingDrop` 解的就是它），
  逐仓才用自己的强平价。混着报会自相矛盾——写这一版时屏幕上真的出现过
  "保证金率 8.6% 安全"底下挂着两行"触及强平价"。
- **临界跌幅用二分搜索，不用解析解。** 对跌幅是线性的，解析解写得出来，但符号很容易
  翻错：净空头的账户里分母会变号，一个漏掉的绝对值就把"永远不会强平"算成
  "跌 3% 就爆"。四十次迭代的代价可以忽略，有测试钉着两头。

口径上的两处简化写在 `lib/stress.ts` 的文件头，都是**偏保守**的方向
（维持保证金按名义等比缩放，忽略 leverageBracket 的档位跳变；保证金余额按 USDT 计价
不随行情变）——宁可把危险说重，不能说轻。

## 标的图标下载进仓库，没有的用字母兜底

`components/Ticker.tsx` + `public/icons/` + `scripts/fetch-icons.mjs`。

**不在运行时引图床。** 那会让每开一次页面，第三方就收到一份"这个账户持有哪些币"的
请求——一个私人资产台不该为了几个图标做这件事。下载下来还顺带解决了离线与缓存。

四个来源，按顺序试、先成的算：**parqet**（按代码给 60×60 品牌色方图，股票与 ETF 的
主力）、**spothq/cryptocurrency-icons**（32×32 圆图，加密货币比 parqet 全）、
**FMP**（PNG 兜底，只有前两个都没有时才用，CRCL / SKHY 这种新上市的）、
**TradingView**（补贵金属 XAU / XAG）。要加新标的就往 `fetch-icons.mjs` 的名单里
补一行再跑一次；它同时重写 `src/components/icons.ts` 那份清单。

**方图与圆图混着无所谓**：组件统一 `rounded-full` 裁成圆的，底下垫一层 `sheet-2`，
透明底的 PNG 也就有了同样的圆盘。不裁的话一列里方一个圆一个，比没有图标还乱。

**清单是生成的，不是运行时探测。** 组件据此决定用图标还是字母——先请求再看 404
的话，每个没有图标的标的都要闪一下才回退。

**覆盖不全是常态，兜底必须好看。** 仍然有抓不到的（SHIB / LUNC 之类），它们走
**带颜色的字母标记**：颜色由代码哈希，同一个标的永远同一个色，扫一列时眼睛能锁住行——那正是
logo 在这里的作用。字母标记的**色相避开 gain / loss / accent**（绿 ≈155°、红 ≈30°、
黄铜 ≈85°）：这套界面里绿红只表示盈亏，一个偏绿的标记会被读成"涨了"。
真图标不受这条约束——它是品牌自己的颜色，形状也认得出来。

用在需要"一眼认出是哪个"的列表上：合约仓位、现货持仓、现金、理财持仓、
合约中的现货持仓、挂单、今日盈亏的逐币。密集的历史表里不放——那里标的是时间下面的
一行小字，再加图标只会更挤。

## 设计约定

- **绿/红只表示盈亏。** 多空方向用中性徽章加箭头；充提在瀑布图里用黄铜色——
  钱转进来不是赚的，染成绿色会被读成盈利。
- **数字一律 `.tnum`**（等宽 + tabular figures），刷新时不左右跳。
- **取不到用 `null`，不用 `0`。** `0` 是一个有效余额。
- **降级按来源分组，不是按整页。** 451 打在 fapi 上只带走合约未实现与当日结算，
  现货涨跌、理财、持仓照常显示；每一节自己知道数据是不是真的。
- **算不出来就留空，不给 0。** 这条贯穿全站：没有报价的币 `value_usd` 是 `null`，
  回滚不平的那天 `pnl_usd` 是 `null`，读失败的列表显示"这次没读到"而不是"没有数据"。
  `0` 与"空账户"都是有效状态，不能拿来顶替"取不到"。
- **过期做成材质**（`.veiled` 降饱和降透明），不是角落一行小字。
- **动效只在承载语义处出现**：`live` 呼吸点会动，陈旧就静止；金额不做滚动动画。
- **模块内部的断点跟着栅格走，不跟着视口走。** `ViewGrid` 在 `lg` 以上才铺成
  12 栏，此后一个 `lg:col-span-4` 的模块只有约 310px 宽——视口却还有 1180px。
  `WalletSpread` 里那份清单曾写着 `sm:grid-cols-2 xl:grid-cols-1`，于是
  1024–1280 这一段里两列每列只剩 140px，而一行要 300px，金额和占比是叠着印的。
  改成 `lg:grid-cols-1`：模块横跨整幅版心时才排两列。
- 字号音阶 11 / 12.5 / 14 / 15 / 17 / 21 / 27 / 40，相邻比值 1.15–1.30，
  层级靠字重与颜色，不靠尺寸跳跃。
