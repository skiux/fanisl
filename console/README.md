# fanisl console

资产台。与 `frontend/`（知识引擎）同源共存，挂在 `/console/` 路径前缀下——
会话 cookie 因此不必跨站。

## 当前状态

后端已接（`GET /portfolio` · `/orders` · `/ledger`，见
`backend/src/analyzer/binance/README.md`）。全站需要登录，未登录只渲染登录页。

`src/api/types.ts` 仍是前后端的契约锚点，字段按 Binance 实际接口对齐：

| 契约字段 | 数据来源 |
|---|---|
| `wallets` | `GET /sapi/v1/asset/wallet/balance` 六个钱包的分布 |
| `spot` | `POST /sapi/v3/asset/getUserAsset` 四种锁定态 |
| `futures` | `GET /fapi/v2/account` + `/fapi/v1/accountConfig` |
| `futures[].liq_distance` | `positionRisk` 给了强平价才有；**给不出就是 null，不拿杠杆倒推** |
| `earn` | `GET /sapi/v1/simple-earn/{flexible,locked}/position` |
| `margin` | `GET /sapi/v1/margin/account` |
| `income` | `GET /fapi/v1/income`（资金费 / 已实现 / 手续费） |
| `transfers` | `GET /sapi/v1/capital/{deposit/hisrec,withdraw/history}` |
| `pnl` | 现货成交重放 + 合约 `positionRisk` / `income`（**不用日快照**，见下） |

**mock 层没有删掉**，它是评审降级态的唯一实用手段——451、限流、Key 失效这些状态
没法靠等来复现，而它们恰恰是这三页设计上最花心思的部分。数据来源默认 `实时`，
mock 场景**只在开发构建里可选**（生产留着这个开关，迟早有人把它停在"数据陈旧"上，
然后以为自己的账户真的陈旧了）。

## 登录

```
App → AuthGate → 三个页面
```

没登录就只渲染登录页，资产台一行都不挂载——与后端那道中间件同一个方向，**默认关**。
做成"渲染应用再各处判断"的话，三个页面各自处理未登录，漏一个就是一屏报错。

| 文件 | 职责 |
|---|---|
| `api/http.ts` | fetch 包装：`credentials: 'include'` · 非 JSON 视为错误 · 401 分流 |
| `api/session.ts` | 会话 store + 登录/退出/改口令 + 管理员接口 |
| `features/auth/AuthGate.tsx` | 闸门 |
| — | 登录页在仓库根的 `shared/login/`，**与知识引擎共用一份** |
| `features/auth/AccountPage.tsx` | 自己的账号（`#/account`）：改口令、看/撤销会话 |
| `features/auth/AdminPage.tsx` | 用户管理（`#/admin`，仅管理员，前后端都拦） |
| `lib/router.ts` | 两级 hash 路由 + `canView(页, 角色)` |
| `index.html` 里的引导脚本 | 首帧之前定下深浅色 |

几处不是随手定的：

- **`credentials: 'include'`**：线上同源浏览器默认带 cookie，本机开发跨端口
  （5175→8000）默认的 `same-origin` 会把它丢掉——症状是"登录成功了但每个请求还是 401"。
- **非 JSON 响应直说是 nginx 的事**：少配一个路径前缀时，API 请求会落到 SPA 兜底返回
  index.html，直接 `JSON.parse` 只会报一句语法错，指不到真正的原因。
- **全局 401 排除 `/auth/*`**：口令输错也是 401，那是表单内的错误；不排除的话输错一次
  就触发全局登出，登录页把自己重置一遍。
- **交互原语用 Radix，不自己写。** 这个项目一度让同一件事长出四套实现：资产页的分节
  导航（90 行，自己量标签宽度画指示条、自己接 ResizeObserver 与 `document.fonts.ready`
  重新量、自己写方向键）、流水页的区间切换、委托页的账户筛选、场景切换器——长相各不
  相同，键盘行为也各不相同。账号菜单更直接：`absolute right-0` 没有碰撞检测，窄屏下
  报头折行之后面板会飘到屏幕外。
  现在"选一个"统一走 `components/controls.tsx` 的 `SegmentedControl`（Radix ToggleGroup），
  弹出面板走 `DropdownMenu`（`collisionPadding` 负责翻转贴边）。视觉仍然是我们自己的；
  交给库的是键盘漫游、`aria-*`、焦点归位、碰撞检测——这些自己写从来不是设计取舍，
  只是把无障碍写错的机会多来一次。
- **日期选择用原生 `<input type="date">`。** 手机上直接调系统选择器，本地化与无障碍
  全是免费的。自己写日历弹层是这类项目最典型的造轮子，写出来还比原生难用。
- **界面上只有数字，没有小字。** 这条来回改了五轮才定下来，规则是：
  - **解释数字怎么算的删掉**——"现货按成本 · 合约按标记价"、"没有统一接口，合并而来"。
    那是口径，属于本文件和 `backend/src/analyzer/binance/README.md`。
  - **把数字翻成一句判断的也删掉**——"安全"、"很近"、"不可用"。它读着像信息，
    其实是把 `4.5%` 换个说法再说一遍，而且只有三格里的一格常年有这句，
    整条摘要条就为它高出一行、还错了位。这类判断改用**颜色**：数字自己转金转红
    （`StripCell.tone`），一个像素都不多占。
  - **影响可信度的警告留下**——"2.48 成本不明"、报头的"3 项取不到"。它不是解释，
    是"下面这个数不全"。这类提示按**状态**出现，不按角色藏：全绿时不出现。
    **但同一句只说一处**：流水页摘要条原本也数了一遍取不到的来源，
    报头拿同一个 `sources` 已经在说了，说两遍只会让人以为是两回事。

  同理删掉的还有流水页的「取数窗口」（端点清单）与「取数成本」（权重、调用次数），
  以及三个页面的页脚口径。角色判断只剩三处真需要的：知识库入口、重新取数按钮、
  凭据排查清单——那三样成员做不了也不该看。

- **要核对数字就点开。** 摘要条的「今日盈亏」「未实现盈亏」可点，开一张构成表：
  这个数由哪几项加起来、每项多少、现货逐个币的数量 × 均价、哪部分成本不明。
  抽屉里**只有数字没有说明**——回答的是"怎么凑出来的"（数据），不是"取自哪个接口"（构造）。

- **净值走势图删了，换成每日盈亏日历。** 那条线画的是日快照拼出来的净值，而快照只有
  现货 / 全仓杠杆 / U 本位三个钱包——把钱从现货挪进理财，线就往下掉一截，看着像亏了。
  一条会因为划转而骗人的曲线不如不要。日历只认成交与结算，划转动不了它。
  日历按**月**浏览（‹ 2026 年 9 月 ›，六行固定高度），区间预设（7/30/90/自定义）
  另管统计范围：区间外的日子照常画出来但压暗、不计入合计。这两件事混成一个的话，
  就会渲染出"8 月从 5 号开始"那种半截月份。自定义直接在日历上点起止，
  且**只有落在可取区间内的日子能选**——否则能选出一段全在未来、区间 0 天的范围。

- **不做 K 线。** K 线要开高低收四个值，"这天赚了多少"只有一个数，照 K 线画就得编三个。
  热力图也不是没用，但那是**年视图**的做法；月视图就该是规规矩矩的日历
  （TradeZella / Tradervue / TradesViz 三家都是这么做的）。

- **主题在首帧之前定，不在组件里定**。切换器住在报头里，而登录页没有报头——
  把初值写在 `<html class>` 上的话，选了浅色的人在登录页永远看到深色，
  其他页面则会先画一帧深色再跳成浅色。判断放在 `index.html` 的内联脚本里，
  `ThemeToggle` 只负责写。两处都判断一次的写法迟早会不一致。
- **成员进 `#/admin` 直接退回资产页**（`canView`，用 `replaceState` 不留历史）。
  后端会 403，但让人先看见"用户管理"的标题再看见一屏错误，是把权限问题讲成了故障；
  而"重新取数"这种按钮在权限问题上按多少次都不会好。
- **管理页的行内操作是文字不是图标**。原先是 13px 的图标，其中"改角色"用的还是一个
  循环箭头——跟报头上"重新取数"同一个符号，指的却是"把成员升成管理员"。
  重置口令走行内的口令输入框，不用 `window.prompt`（原生框里口令是明文）。
- **自己那一行不给任何管理动作**，只留一条去「账号」页的链接。停用和删除后端本来就拒绝，
  降级后端过去不拒绝——手一抖就把自己踢出管理面，且只能求另一个管理员捞回来。
- **管理页不复制后端的判定规则**（最后一个在岗管理员不能停用/降级/删除、不能删自己）。
  前端复制一遍必然与后端漂移，而漂移方向通常是前端更松。这里只把 409 的原话显示出来。
- **账号页与用户管理页的纸张按内容收**，不钉在视口高度——那两页内容不多，钉住只会在
  下面留一大片空白。数据页要钉住是另一回事：那是为了让切换分节时页面高度波动为 0。
- **「没有数据」与「为什么没有」分开判**。原来写的是"每个来源都 unauthorized"，
  而 `prices` 是公开端点、没有 key 也照常返回，于是这个条件再也不成立——
  没配 key 会被误报成"账户里还没有资产"，屏幕上还留着一句"前往 Binance"，方向指反了。

## 命令

```bash
npm install
npm run dev          # http://127.0.0.1:5175/console/
npm test             # vitest：http 层、会话、路由与权限
npm run typecheck
npm run lint         # 见下，别跳过
npm run build
```

**`npx tsc --noEmit` 什么都不查。** 这份 tsconfig 是 solution 式的（只有
`references`，没有自己的 `files`/`include`），不带 `-b` 时 tsc 找不到任何输入文件，
安安静静退出 0。要查类型只有 `npm run typecheck`（`tsc -b`）。
2026-09-05 踩过：拿 `--noEmit` 连着"验"了四遍全绿，换成 `-b` 一次冒出四个错。

**`npm run lint` 不是可选的。** 这个项目原先没有 lint，代价是实打实的：
`RealizedDays` 把空数组的守卫写在几个 `useMemo` 之后——hook 先跑、守卫永远轮不到，
合约域名 451 时 `pnl` 为空，整页白屏（两个场景六个页面全白）。TypeScript 查不出来，
人眼也看不住，只有 `react-hooks/rules-of-hooks` 能拦。加上 lint 的当天它就又抓到
一处同类（`StatementPage` 的详情抽屉 `useState` 写在了两个提前 return 之后）。

规则**只开正确性两条**，没开整套 recommended——新版插件里还带着一批 React Compiler
的风格规则（effect 里不许 setState 之类），要满足它们得把取数逻辑整个重写，
那是另一件事。

## 降级态怎么验

`?scenario=` 切换十种 mock 状态（`src/api/client.ts` 的 `SCENARIOS`）。
**每次改完至少扫一遍全部场景 × 全部页面**，只测 `ok` 是不够的——上面那次白屏就是
`fapi_blocked` 与 `no_history` 两个场景独有，而它们在 `ok` 下永远不出现。

```
ok · stale · fapi_blocked · all_blocked · no_history · unauthorized · empty · loading · down
```

扫的时候看四样：控制台报错、页面几乎空白、横向溢出、渲染出 `NaN` / `undefined`。

mock 层**不能删**：451、限流、Key 失效这些状态没法靠等来复现，而它们恰恰是这三页
设计上最花心思的部分。场景开关**只在开发构建里可选**（`import.meta.env.DEV`）——
生产留着它，迟早有人把它停在"数据陈旧"上，然后以为自己的账户真的陈旧了。

## 形态

报头 → 常驻摘要条 → 分节导航 → 明细区 → 页脚。

```
┌──────────────────────────────────────────────┐
│ 资产报表            截至 · 来源 · 计价 · 取数  │
├──────────────────────────────────────────────┤
│ 净值        今日盈亏   未实现盈亏   合约保证金率  │
│ $80,141.23  +$1,018.38  +$2,960.81      17.5%  │
├──────────────────────────────────────────────┤
│ 总览  本期变动  现货  理财  合约  风险         │  ← 指示条滑动
├──────────────────────────────────────────────┤
│            选中的那一节（整幅宽度）             │
│            区域内部滚动                        │
├──────────────────────────────────────────────┤
│ 口径                              来源 9/9    │
└──────────────────────────────────────────────┘
```

- **导航横向、小字、无底框**，靠一条走 `transform` 的指示条滑动建立连续感——
  不是逐个元素的下边框一闪一灭。指示条随字体加载和容器尺寸变化重新测量。
- **摘要与导航分开**：导航只管导航，四个关键数字另立一条常驻条。
  （曾把两件事塞进一根侧栏，结果既不像导航也不像摘要，还吃掉 224px 宽度。）
  三个数据页共用 `components/Strip.tsx`，对齐规则见下节——**那里改之前先读它**。
- 桌面把整张纸钉在视口内、明细区内部滚，**切换分节时页面高度波动为 0**。
- 外壳压到视口的 40%，明细区拿到 60%——第一版外壳占了一半，比例失衡。
- 降级在摘要条与标签上都看得见（`—/取不到`、标签旁的红点）。
- 短标签让六个分节在 390px 下也能一行放完；完整名称留在各视图抬头。
- 视图状态进 hash（`#/spot`），可直接链到某一节。

纸张与三种字体的身份沿用：标题 Newsreader（衬线），标签 Geist，数字 Geist Mono
（tabular）。浅色为主设计目标，深色是同一份报表在暗处的读法。

## 摘要条的对齐

`components/Strip.tsx`，资产 / 委托 / 流水共用。一个主数字（40px）加两到三个指标
（21px），横排。**这处几何改坏过四次**，写在这里免得第五次：

一排里字号不同的数字，同时想要三件事——

1. 标签落在同一条线上
2. 数字落在同一条线上
3. 每格里标签到数字的距离一样

拿**基线**当第 2 条的那条线，就必然要牺牲第 3 条：字号不同而基线相同，
意味着矮的那个整体下沉（下沉量 = 字号差 × 上伸部系数，40px 与 21px 之间约 20px），
这 20px 只能从它的标签底下挤出来，标签就飘了。反过来底对齐（`items-end`）保住 2、3，
断掉的是 1：有第三行的那格整块下移。四次改动就在这两个错之间来回换。

出路是**别拿基线当那条线**。`leading-none` 下顶对齐得到的是一条字身顶线，
实测 40px 的 `$48,626.33` 与 21px 的 `+$236.42`，墨迹顶只差 0.86px——
肉眼就是一条线。于是：

```
items-start（容器）+ mt-2（每格内部，两档共用）
```

三条同时成立，标签基线四格完全重合。**别再往里加 padding 去"对基线"。**

顺带两条同源的约束：

- **每格只有标签和数字两行，没有第三行。** 三格里只有一格常年有小注的话，
  那两个字既撑高整条又让这格跟邻居不齐。要提醒就用 `tone`。
- **窄屏用 `grid grid-cols-2`，不是 flex。** flex 下第二列的 x 取决于第一格数字
  有多长，`+$236.42` 变成 `+$1,236.42` 整列就挪一次。

量这类东西**不要用 `getBoundingClientRect`**：它给的是行盒，不是基线也不是墨迹。
要基线就用 `Range.getClientRects()` 的顶 + canvas `measureText` 的
`fontBoundingBoxAscent / 1000 × 字号`；要墨迹顶就再减 `actualBoundingBoxAscent`。
拿行盒或空 `inline-block` 探针量出来的数一次都没对过。

## 现货成本可以人手填

`#/costbasis`（账号菜单进，**仅管理员**）。

现货未实现盈亏来自成交重放（`myTrades`），但有几条进账的路它照不到：钱包划转、
理财派息、小额兑换、闪兑，以及 **90 天以前的充值**——那个接口再也查不回来。
重放于是把那部分标成"成本不明"，不计入盈亏，屏幕上的数偏小。缺的是历史，不是算法。

这一页让知道的人把均价直接报出来，填了就整仓按它算：

    未实现 = 持有量 × (现价 − 录入均价)

几条规则：

- **持有量不手填**，取自接口，而且是**跨全部钱包**的——划进合约当保证金的 BNB 也算。
  能填的只有均价。
- **只改未实现，不改已实现。** 一个当前的均价回答不了过去那些卖出是赚是赔。
- **列表遍历的是"余额 ∪ 重放 ∪ 录入"**，不只是重放。整仓划进合约、从没在现货买过
  的币，重放里根本没有它——只从重放出发的话它整行消失，也就没有地方给它录均价。
- **会过期，而且不会自己报警。** 加仓之后录的均价就不管整仓了，所以录入时把当时的
  持有量一并存下（`qty_at_entry`），列表拿它跟现在的持有量比，对不上就标"持有量变了"。
- 清除 = 退回成交重放的口径，不是退回"没有盈亏"。

mock 场景下这一页走内存（`client.ts` 的 `mockCostBasis` + `applyCostBasis`），
按后端同一条规则把录入盖到快照上。不这么做的话，mock 里点了保存屏幕上什么都不动，
而"改了没生效"恰恰是这一页最该讲清楚的事。

## 风险阈值只有一份

`lib/risk.ts`。合约保证金率原先在同一屏上按三套标准判——风险仪表在 0.6 转红，
而它自己在 0.8 处画着"危险线"（条早在红线之前就红了），摘要条又是第三套；
数字还印了两种精度，`4.5%` 与 `4.46%`，看着像两个数。

规则：**判色、判语、仪表上那条标记线，三样取自同一组常数；同一个量全站同一档小数位。**
保证金率取 0.5 偏紧 / 0.8 危险（到 100% 就是强平，0.8 只剩两成缓冲，
也正是仪表本来画的那条线）。强平距离是另一把尺，别跟它混。

判语（"安全""偏紧"）只留在**风险仪表**里：那里有一条带颜色的进度条，
判语是这个颜色的说明，色觉障碍的人靠它读同一件事。摘要条没有条也没有图例，
判语在那里只是把 `4.5%` 换个说法再说一遍——所以摘要条只上色，不写字。

## 设计约定

- **绿/红只表示盈亏。** 多空方向用中性徽章加箭头；充提在瀑布图里用黄铜色——
  钱转进来不是赚的，染成绿色会被读成盈利。
- **数字一律 `.tnum`**（等宽 + tabular figures），刷新时不左右跳。
- **取不到用 `null`，不用 `0`。** `0` 是一个有效余额。
- **降级按来源分组，不是按整页。** 451 打在 fapi 上只带走合约与收支流水，
  现货、理财、日快照照常显示；每一节自己知道数据是不是真的。
- **归因算不出来就空着。** 恒等式
  `期末 = 期初 + 净充提 + 已实现 + 未实现变动 + 资金费 + 手续费`
  缺任一项就不闭合，与其给对不上账的图不如不给。
- **过期做成材质**（`.veiled` 降饱和降透明），不是角落一行小字。
- **动效只在承载语义处出现**：`live` 呼吸点会动，陈旧就静止；金额不做滚动动画。
- 字号音阶 11 / 12.5 / 14 / 15 / 17 / 21 / 27 / 40，相邻比值 1.15–1.30，
  层级靠字重与颜色，不靠尺寸跳跃。
