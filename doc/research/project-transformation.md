## 0. 一句话

**旧范式**：给 Claude 喂一张 50 指标快照，问"现在该不该交易"——酌情、同步指标、低 edge、小 N 不可测，结构上注定"几乎永远不进场 + 进场即烂 RR"。

**新范式**：一个**研究→验证→部署→再验证**的闭环。Claude 生成可证伪的假设 → 引擎在历史上回测 → 统计验证（带前向收益标签 + 基准对照）→ **只有被验证的 edge 才部署** → 持续监控衰减。Claude 的角色从"实时数字判官"变为三件它真正擅长的事：**假设生成器 / 非结构化数据解读者 / 受约束的酌情否决者**。

核心洞察：**"几乎不进场"不是要修的 bug，是信号——它在说"快照 TA 这个框架里没有机会"。解法不是让 Claude 更激进，而是给它一个值得有信念的框架（带先验、被历史验证过的 setup）。**

---

## 1. 为什么必须转（存在性风险复述）

当前项目把绝大部分精力投在**测量装置**（多账户、scorecard v2、校准、影子、引擎裁决）上，却从未验证过核心假设——**"Claude 交易有没有 edge"**。而它采用的策略框架（单张快照的多周期 TA + 酌情判断）**在构造上就是低 edge 的**：

- 技术指标是同步指标、商品化、早被定价；
- "多周期共振"要求 = 只在趋势已明显时进场 = 追晚了 = 烂 RR（你每个计划 RR<2 被 flag 的根因）；
- 50 个半冲突的数字 + 无先验 = 产出一面 caveat 墙、没有 conviction → 理性输出就是"不交易"。

**最大风险：把测量做到完美，却永远找不到 edge，因为输入信号里没有 edge。** 必须先回答"有没有 edge"，再谈测量它。

## 2. 目标架构（4 层 + 1 闭环）

```
                    ┌─────────────── 研究闭环（核心循环）───────────────┐
                    │                                                   │
   ① 假设          ②  回测/重放            ③ 统计验证         ④ 决策门    │
  (Claude+人)  →   (引擎，廉价批量)   →   (前向收益+基准)  →  edge?      │
       ↑                                                    ├─ 否 → 杀掉+存档（负结果一等公民）
       │                                                    └─ 是 → ⑤ 固化为 playbook
       │                                                              │
       └──────────────  ⑦ 监控/衰减/regime  ←  ⑥ 受约束实盘(评测台)  ←┘

  ───────────────────── 基础层（point-in-time，不可妥协）─────────────────────
  时点正确的数据   +   特征库(versioned)   +   前向收益标签(多horizon/风险调整)
  ─────────────────────────────────────────────────────────────────────────
  执行/会计引擎（复用现有）——回测与实盘共用同一撮合/滑点/费用/强平逻辑
```

**四层：**

1. **基础层（point-in-time 数据 + 特征库 + 标签）**——新项目的地基，当前最缺的纪律。
   - **时点正确（no lookahead）**：每个特征必须是"在时刻 T 当时已知的值"。这是回测有效性的命根子，一旦有未来函数，所有回测结论作废。
   - **前向收益标签**：对每个 (标的, 时刻)，预计算多 horizon（1h/4h/1d…）前向收益 + 风险调整版（除以 ATR、相对基准）。**没有标签就无法度量任何特征的预测力。**
   - **特征库**：原始数据 → 工程化特征（不是裸 RSI，而是归一化 / regime 条件化 / 横截面排名后的信号），versioned、可复现。

2. **回测/重放引擎**——**当前最缺、杠杆最高的新能力**。
   - 按 bar 回放历史，喂时点特征给策略，**复用现有执行引擎**模拟撮合/费用/滑点/强平，产出跨数千次决策的 track record。
   - 两层：**(a) 确定性规则回测**（无 Claude，秒级跑完多年，用来筛 setup）；**(b) Claude-in-loop 回测**（贵，只抽样跑酌情层的模糊案例）。
   - 价值：几分钟测几千个决策，而不是前向实盘等几周。**这是把项目从"龟速积累"变成"快速迭代"的关键。**

3. **Playbook 层**——被验证的 edge → 参数化 setup（进场/出场/仓位规则 + 实测先验：命中率、期望、适用 regime）。

4. **评测层（你已建好的，重新定位）**——评 **setup 类型**的 edge（N 次里赚不赚），不是评单笔判断；影子扩成多个**基准**（随机进场 / 简单动量 / buy&hold），让结果可解读。

**闭环七步**：假设 → 回测 → 验证 → 决策门(edge?) → 固化playbook → 受约束实盘 → 监控衰减 → 回到假设。

## 4. 分阶段计划（按"先消除存在性不确定"排序，每阶段一个决策门）

> 排序原则：**先回答"有没有 edge"这个可能致命的问题，再投入放大/产品化。** 每阶段结束必须能回答一个 yes/no，否则不进下一阶段。

### Phase 0 — 承诺转变 + 锁定第一个假设（1 天，纸面）
- 决定接受范式转变；写下**第一个要测的具体假设**（见 §8）。
- 定义成功标准：什么 edge、需要多大 N、什么显著性、留多少 out-of-sample。**先写判据，再看结果**（防事后找补）。
- **门**：假设可证伪、判据明确 → 进 Phase 1。

### Phase 1 — 地基 + 回测引擎（最关键，make-or-break）
- 把现有数据改造成**时点可查**；为 BTC/ETH 等核心标的预计算**前向收益标签**。
- 造**确定性回测引擎**，复用现有撮合/会计。让**一个**规则策略端到端在现有历史上跑出 track record。
- **门**：能在历史上跑完一个策略、产出含费用/滑点的客观 PnL 曲线 + 基准对照 → 进 Phase 2。**这一关过不了，后面全是空中楼阁。**

### Phase 2 — Edge 发现（回答"现有数据里有没有 edge"）
- 系统化做**特征 → 前向收益**分析：信息系数(IC)、按分位的命中率、衰减曲线。先用现有数据（funding/OI/LSR/爆仓/链上）。
- Claude 当假设生成器：基于数据现象提"若 X 则前向 Y"的可证伪命题；引擎回测；Claude 解读结果、迭代。
- **门**：产出**至少一个被验证或被明确杀掉**的 edge。
  - 有 edge → 进 Phase 4（先用现有数据的 edge 实盘验证）。
  - 没有 edge → 进 Phase 3（现有数据不够，去补带 edge 的数据），或如实记录"快照 TA 无 edge"这个有价值的负结果。

### Phase 3 — 数据扩张（**只在知道猎什么 edge 之后**）
- 按 §5 的标准补**正交、时点、可历史化**的 edge 源。Phase 2 指向哪儿就补哪儿，不漫无目的铺广度。
- **门**：新数据上重做 Phase 2 的发现，确认它带来增量预测力 → 否则砍掉这个数据源。

### Phase 4 — Playbook + 受约束实盘
- 验证过的 edge → 参数化 setup。实盘 = 匹配当前条件到 playbook；**Claude 的酌情角色收窄到"这是不是 setup X 的干净实例 + 有无定性否决理由"**——一个比"该不该交易"高 edge 得多的窄问题。
- 重新定位评测台：按 setup 类型评 edge + 多基准影子对照。
- **门**：实盘的 setup 表现与回测先验一致（无重大 live-vs-backtest 落差）→ 进 Phase 5。

### Phase 5 — 持续研究循环
- 衰减监控（edge 会消失）、regime 切换检测、定期再验证；复盘 lessons → 新假设，飞轮转起来。

## 5. 数据战略（你说能拿到任何数据 → 那就按"质量与正交性"选，不按"好不好拿"选）

**选数据的四个硬标准**（任缺其一就先别投入）：
1. **能时点采集**：必须能还原"时刻 T 当时的值"，否则回测无效。
2. **可历史化**：能回填或能从现在起前向积累到足够 N。
3. **正交**：和已有信号不重叠——补的是新维度，不是第 200 个技术指标。
4. **有经济理由**：能讲清"为什么这会带 edge"（谁在被迫交易、什么结构性失衡），否则极可能是过拟合噪声。

**优先补的高 edge 源（按价值）：**
- **订单流 / CVD / 主动买卖失衡**——最接近"谁在用力"的真实信号。
- **持仓极值的深历史**：资金费率、OI、多空比（散户 vs 大户）——挤压/去杠杆的燃料。
- **爆仓历史**：连环清算是行情加速的物理引擎，你现在只有快照。
- **链上流向带时点**：交易所净流入流出、巨鲸、稳定币增发/销毁时点。
- **资金/ETF 流带时点**、**带精确时间戳的催化剂日历 + 新闻事件流**（做 event-study：事件后漂移是经典 edge）。

**"文档即数据"**：没有 API 的（定性 regime 标注、事件注释、人工判断），用**带时间戳、结构化的 markdown/JSON 日志**记录，同样可查询、可回测。怕复杂就先记得糙但**带准确时点**——时点比精致重要。

**反面提醒**：能拿到任何数据 ≠ 该拿任何数据。每加一个源都增加过拟合的自由度（见 §6）。**先有假设，再为假设取数。**

## 6. 不自欺的护栏（quant 项目最容易骗自己，这节是命门）

1. **时点纪律（lookahead bias）**：回测里只能用"当时已知"的数据。最隐蔽的杀手——指标用未来 K 线收盘、标签泄漏进特征、用了"后来才修订"的宏观数据……一旦有，回测 PnL 全是幻觉。
2. **样本外 / holdout**：留一段历史永不参与调参，只在最后验一次。in-sample 漂亮毫无意义。
3. **多重检验 / 过拟合**：测 1000 个特征必然能"找到"几个虚假显著的。要么 Bonferroni/FDR 校正，要么严格 holdout，要么要求经济理由先行。**数据越多，这个陷阱越深**——这正是"你能拿到任何数据"的反作用力。
4. **显著性门**：Phase 0 就写死 N、显著性、out-of-sample 标准，到了才信。
5. **负结果一等公民**：快速杀假设、存档。"这条没 edge"和"这条有 edge"一样是进展。
6. **每个工作项都要过一句话审问**："它如何让我更接近'有没有 edge'的 yes/no？" 答不上来就是伪进展，暂缓。
7. **回测先于实盘**：实盘只跑被验证的 edge；实盘是验证，不是探索。

## 7. Claude 的新角色（具体，且保守问题自然消解）

旧框架问 Claude 开放问题"该不该交易？"→ 50 指标里永远有反证 → 理性 decline。**新框架不问这个。**

Claude 的三个角色（都发挥它的长处，避开"实时数字判官"这个短处）：
1. **假设生成器**：基于数据现象和市场理解，提可证伪的 setup 命题。这是创造性工作，LLM 强。
2. **非结构化数据解读者**：读催化剂/新闻/事件/regime 叙事——纯量化难编码、Claude 强的地方。把定性信息转成结构化标注喂回特征库。
3. **受约束的酌情否决者**：当一个**被验证的 setup** 触发时，Claude 只判"这是不是干净实例 + 有无定性否决理由（如临近黑天鹅事件）"。**先验来自回测，不来自 Claude 盯 50 个指标**——所以它有信念、不再无脑 decline。**保守问题在这个框架里自然消失。**

**成本经济学**：Claude-in-loop 回测贵。解法——**确定性 setup 检测廉价穷举回测，Claude 只在(a)离线设计规则、(b)实盘抽样否决模糊案例时介入**。这样放大 N 不会烧爆预算。

## 8. 第一个要测的假设（具体，用你**现有**数据，今天就能开干）

**假设**：当**资金费率处于历史低分位（深度为负）且 24h 爆仓以多头为主（或 OI 背离=price_down_oi_down 去杠杆）**时，未来 4–12h 出现均值回归反弹的概率显著高于基线，且风险调整后期望为正。

- **经济理由**：极端负资金费 + 多头被清算 = 空头拥挤 + 去杠杆出清，反弹燃料充足（轧空）。这是有结构性逻辑的、可重复的失衡，不是"读图判断"。
- **你已有的数据够测**：funding_rate/percentile、OI、liquidations、LSR、价格前向收益。
- **判据（Phase 0 先写死）**：在 BTC/ETH/SOL 上，过去 N 个月、信号触发 ≥30 次，4h 前向收益命中率 vs 基线（随机/全样本均值）有统计显著优势，且扣费后期望 > 0、out-of-sample 不崩。
- **结果两条路**：成立 → 第一个 playbook setup + 上实盘验证；不成立 → 杀掉、换下一个假设（也许就该转去补订单流数据）。

无论成败，你**第一次**拿到了关于 edge 的一手证据——这比再建一层评测有价值得多。

## 9. 转变本身的风险 + 去风险

- **风险：又陷入"无限准备"**（这次变成"无限造特征/回测框架"）。**去风险**：Phase 1 只为跑通**一个**策略而造最小回测引擎，不追求通用框架；Phase 2 只测**一个**假设。先窄、先快、先拿到 yes/no。
- **风险：把回测引擎做成大工程**。**去风险**：复用现有执行引擎，回测引擎只是"按时间喂数据 + 调用现有撮合"的循环，先糙后精。
- **风险：过拟合自欺**（数据多了更危险）。**去风险**：§6 护栏，尤其 holdout + 经济理由先行。
- **风险：误以为要重写**。**去风险**：§3 的保留清单，70% 复用，转变是加两根支柱 + 改数据层 + 换提示词框架。
- **风险：Claude-in-loop 成本失控**。**去风险**：§7 的"确定性穷举 + Claude 抽样"分层。

## 10. 落地顺序（最小路径）

1. Phase 0：写下第一个假设 + 判据（§8）。半天。
2. Phase 1：核心标的前向收益标签 + 最小回测引擎（复用执行引擎）。跑通一个策略。
3. Phase 2：测 §8 那个假设 → 第一手 edge yes/no。
4. 据结果：有→Playbook+实盘验证；无→补订单流/爆仓深历史(§5)再测，或记录负结果。
5. 之后才考虑放大、产品化、更多评测指标。

**北极星**：每一步都在缩小"有没有 edge"的不确定，而不是在打磨一个还没证明有用的装置。
