## 各层选型

**前端 · React + TS(Vite)** 对话三件套：消息列表、输入框、流式渲染。配
`react-markdown` 渲染 Claude 的回复，Tailwind + shadcn/ui 撑门面(taste-skill
)。不要图表库,这版纯文字。

**传输 · FastAPI + SSE** 一个 `/chat` 接口，Server-Sent
Events 流式推回复。**v1 可以先不流式**(等完整回复再返回),跑通逻辑后再加 SSE——流式 + 工具调用交错处理是这版最磨人的部分,别一上来就啃。

**Agent 循环 · anthropic SDK(原生 tool use)**
这是新架构的心脏。Claude 在一轮对话里可以反复调工具：请求工具→后端执行→塞回结果→Claude 继续，直到产出自然语言回复。这套用 SDK 原生的 tool
use 实现。

**行情工具 · CCXT + pandas-ta + 快照组装**
之前设计的三层(采集/指标/快照)原封不动保留，只是**打包成一个工具函数**
`get_market_snapshot(symbol, timeframes)`。内部仍是 CCXT 拉数→pandas-ta 算→阈值化成语义快照。数据源依旧做成可插拔接口,留好扩股票的口子。

**存储 · SQLite** 两张表：`conversations` 和
`messages`(含 role、内容、tool_use/tool_result)。每轮把完整历史喂回 Claude。

## 核心：工具循环（`agent.py` 骨架）

整个项目最关键的一段，理解这个循环就理解了整个后端：

```python
TOOLS = [{
    "name": "get_market_snapshot",
    "description": "获取某交易对多周期行情快照（已算好指标 + 衍生品情绪）",
    "input_schema": {
        "type": "object",
        "properties": {
            "symbol": {"type": "string", "description": "如 BTC/USDT"},
            "timeframes": {"type": "array", "items": {"type": "string"},
                           "description": "如 ['1h','4h','1d']，默认全给"},
        },
        "required": ["symbol"],
    },
}]

def run_turn(history: list[dict]) -> list[dict]:
    while True:
        resp = client.messages.create(
            model="claude-opus-4-8", max_tokens=2000,
            system=SYSTEM_PROMPT, tools=TOOLS, messages=history,
        )
        history.append({"role": "assistant", "content": resp.content})
        if resp.stop_reason != "tool_use":
            return history                      # Claude 给出最终回复，结束
        # Claude 要调工具：执行后把结果塞回，继续循环
        results = [dispatch_tool(b) for b in resp.content if b.type == "tool_use"]
        history.append({"role": "user", "content": results})
```

`dispatch_tool` 就是调 `get_market_snapshot`(内部 CCXT→pandas-ta→快照),把
`MarketSnapshot.model_dump()` 作为 `tool_result`
返回。系统提示词里钉死它的角色：**只是分析助手，用工具取真实数据、绝不编数字、给推理过程、不下买卖结论。**
