# 前端修复与验证计划

更新于 2026-08-14。本文用于约束本轮前端整改的顺序、边界和验收方式。任何视觉重构都排在数据正确性、生产可用性和交互正确性之后。

## 当前基线

- 前端：React 19、TypeScript、Vite 8，hash 路由，页面样式目前通过全局 CSS 汇总。
- 后端：FastAPI，知识相关接口位于 `/knowledge/*`，研究档案接口位于 `/research/*`。
- 生产：nginx 同时提供静态前端和同源 API 反向代理。
- 数据规模（2026-08-14 本机接口实测）：49 条原始内容、798 个知识单元、448 个长期知识节点；整改前知识证据页只请求并渲染前 500 条、长期知识只请求前 300 条、验证页只请求前 120 条。
- 质量基线：`lint`、`typecheck`、严格 TypeScript 检查和生产构建通过；仓库尚无前端自动化测试。

## 已确认的问题

| 等级 | 问题 | 直接影响 | 本轮处理 |
| --- | --- | --- | --- |
| P0 | nginx 未代理 `/knowledge` 与 `/research` | 同源生产构建会把 API 请求回退为 `index.html` | 阶段 1 |
| P0 | 首页数字和搜索样本是过期静态值 | 用户看到错误规模，搜索并非真实知识搜索 | 阶段 1 |
| P0 | 知识与验证接口结果被固定 `limit` 截断 | 页面把局部数据误呈现为全库数据 | 阶段 2 |
| P0 | 长期知识索引只请求前 300 个节点 | 148 个节点无法搜索和打开 | 阶段 5 补齐 |
| P1 | 证据档案与知识页共享 `.unit-scores` 全局类名 | 档案版式被后加载的页面样式覆盖 | 阶段 3 |
| P1 | 已不可达的时间线/周报界面仍保留大段实现与样式 | 维护成本、串扰概率和构建体积持续增加 | 阶段 3 |
| P1 | 首页存在 3 个持续运行的动画循环 | 空闲状态仍高频读写 DOM/SVG | 阶段 4 |
| P1 | 所有路由和样式一次性进入首屏包 | 首页承担知识、验证、发现和档案代码成本 | 阶段 4 |
| P1 | 弹层未完整管理焦点、背景惰性和关闭后焦点恢复 | 键盘用户可离开弹层，层级关系也会错乱 | 阶段 5 |
| P2 | API 响应只做 TypeScript 强制断言，无超时和运行时校验 | HTML 回退、畸形数据和慢请求难以被正确识别 | 阶段 5 |
| P2 | 无前端测试和固定回归基线 | 每轮样式或数据修改都依赖人工记忆 | 阶段 6 |

## 阶段与完成门槛

### 阶段 1：生产正确性与首页语义

1. 补全 nginx 的知识与研究路由代理，并增加可自动执行的配置契约检查。
2. 首页统计只展示接口返回的真实数据；失败时明确显示不可用状态，不用旧样本伪装实时数据。
3. 首页搜索接入知识单元全文检索，并让结果落到对应证据详情；导航栏搜索统一进入同一真实搜索入口。

完成门槛：开发环境和生产预览中，知识、研究 API 返回 JSON；首页无硬编码规模；真实关键字可打开对应知识证据；失败态可见且可重试。

### 阶段 2：完整数据与长列表

1. 为知识单元和验证队列补充可确定排序的分页契约以及总数/是否还有下一页信息。
2. 前端保留当前阅读工作区，但仅挂载视口附近的行；筛选、搜索、选中项和返回位置不能丢失。
3. 页面必须区分“已加载数量”和“全库总量”，禁止再用局部数组长度充当总量。

完成门槛：798 个知识单元均可被搜索和到达；初始 DOM 不随全库行数线性增长；快速滚动无明显空白闪烁；验证各分组总数正确。

### 阶段 3：样式边界与死代码清理

1. 先通过类名改写和路由根节点作用域消除已确认的冲突，再逐页迁移路由私有样式。
2. 只删除由引用图和浏览器路由验证共同确认不可达的组件、导出与样式。
3. 统一设计令牌、字号下限、间距、边框和语义色；不在这一阶段推翻现有信息架构。

完成门槛：证据档案不再继承知识卡片样式；无孤立导入；全路由截图对比仅出现预期变化；CSS 体积有可量化下降。

### 阶段 4：加载与动画性能

1. 以路由为边界使用 `lazy`/`Suspense`，让 Vite 生成独立 JavaScript 与 CSS 分块。
2. 首页只保留一个动画调度器；无滚动变化时停止逐帧写入，后台页签和 reduced-motion 下不运行装饰动画。
3. 图片采用明确尺寸、延迟加载和本地兜底策略；未使用资源不进入发布目录。

完成门槛：首页初始包不包含其余四个页面主体代码；空闲动画写入接近零；切换路由无样式闪烁；生产构建分块和体积记录入档。

### 阶段 5：交互、可访问性与故障边界

1. 弹层打开后焦点进入弹层，Tab 循环限制在弹层内，背景不可交互，Escape 关闭，关闭后焦点回到触发器。
2. 为 tab、dialog、状态提示补齐名称、关联属性和键盘行为。
3. 修正详情页历史记录，关闭详情不制造重复历史；无效深链回到可解释的空状态或规范 URL。
4. API 客户端增加超时、内容类型检查和关键响应的运行时校验；路由级错误边界提供恢复动作。
5. 长期知识改用稳定分页契约读取全量节点，修正带多评分节点的提及数重复统计。

完成门槛：纯键盘可完成搜索、筛选、打开和关闭所有档案；浏览器前进/后退状态一致；后端关闭或返回 HTML 时页面不崩溃也不误显示预览数据。

### 阶段 6：自动回归体系

1. Vitest：格式化、路由解析、数据适配器、API 异常和关键交互单元测试。
2. Playwright：五条主路由、真实搜索、详情历史、弹层键盘、生产代理、窄屏和宽屏流程。
3. 视觉基线：固定浏览器与视口，仅对稳定区域建立截图基线；动画和时间字段在截图时冻结。
4. 每阶段统一执行 `lint`、`typecheck`、严格 TypeScript、测试、生产构建和 `git diff --check`。

完成门槛：关键用户路径有自动断言；桌面与移动视口无横向溢出；控制台无未处理错误；视觉差异必须可审阅。

当前基线（2026-08-14）：5 个 Vitest 文件共 10 条断言；Playwright 22 条用例，覆盖五条主路由、真实搜索、详情历史、弹层焦点、键盘 tab、桌面/移动溢出与四张稳定区域截图。首次生成基线时发现并修复了知识页标题重叠，随后无更新参数复跑全部通过。

## 实施边界

- 当前未提交的后端文件保持不动。阶段 2 若必须修改 `knowledge/store.py`，先拆分并确认与现有改动的差异，不覆盖或格式化用户修改。
- 不以预览数据掩盖接口错误。预览只能有明确标识，且不能显示为当前数据库统计。
- 不在没有调用图、运行时路由和构建验证三项证据时删除旧实现。
- 不以一次截图替代验证。每个阶段至少包含功能断言、浏览器检查、控制台检查和生产构建检查。

## 设计与实现依据

- nginx 的正则 `location` 与 `proxy_pass` 规则决定同源 API 是否被交给后端。
- React `lazy` 与 `Suspense` 用于按路由延后载入代码；Vite 会为异步模块拆分并按需加载对应 CSS。
- 长列表采用服务端分页与视口虚拟化组合，避免“只加载一部分”与“一次挂载全部 DOM”两个极端。
- 模态交互遵循 WAI-ARIA APG：焦点进入并保持在弹层内，背景惰性，Escape 关闭，关闭后恢复焦点。
- 自动测试使用与 Vite 共用转换配置的 Vitest，以及能断言可访问名称、截图和生产流程的 Playwright。
