# Fanisl Design Philosophy（设计哲学）

> 2026-07-17。本文是前端重设计的**宪法层**：只回答"这个产品是什么、给谁用、按什么原则组织信息"。
> 页面结构（IA spec）与视觉规范（DESIGN.md：token/组件/护栏）由本文推导，后续另立文档。
> 本文不讨论 React、CSS、组件。

---

## 0. 打开 Fanisl 的那一刻，用户进入了什么

不是 Bloomberg，不是 GitHub，不是 Notion，不是 TradingView，也不是 Linear。
这些产品各答对了一部分，但没有一个的心智可以整体照搬：

- Bloomberg 的主动词是**盯**（秒级决策）；Fanisl 的验证按天成熟，装成实时终端是表演。
- Notion/Obsidian 的主动词是**写**；Fanisl 的知识由机器提取入库，人不手写知识。
- TradingView 的主对象是**图**；Fanisl 的主对象是**有出处、有战绩的判断**。
- Linear 的主对象是**任务**；Fanisl 没有任务，只有持续积累的档案。
- GitHub 最接近——但 GitHub 是协作平台，Fanisl 是单人仪器。

正确的感受是：**走进自己的研究室**。这个房间有三个纵深：

1. **桌面**——今天新到的材料、刚出炉的验证结果、知识状态的变化；
2. **档案**——全部积累：每一篇内容、每一条判断、每一次裁决，永久、可检索、可追溯；
3. **仪表**——墙上的市场数据，平时安静，作证时被调出。

前台是一本**持续自我更新的研究刊物**，后台是一台**持续运转的验证机器**。
界面的职责是让人**读见机器的工作**，而不是去操作机器。

若必须写成配方：GitHub 的证据纪律 × Obsidian/Notion 的阅读与永久积累 ×
Bloomberg 的数字严肃性（仅限数据层）× Apple Health 的"系统自采集、定期给人可读的摘要"。
合成结果是一种新的体验：**私人金融研究终端**——不是给别人看的产品，是给自己用十年的仪器。

## 1. 设计从五个事实推导，不从审美偏好推导

设计哲学若不能从项目事实中推出来，就只是风格偏好。Fanisl 的五个事实：

**① 单用户。** 没有协作、权限、租户、营销页。不存在"给访客留下印象"的页面，
不需要 onboarding 漏斗和空态推销。每个像素只服务一个已经完全理解系统的读者。
推论：可以大胆使用领域术语（PIT、ScoringSpec、含糊率），不做解释性冗余；
但也因此，**界面唯一的对手是三个月后忘记细节的自己**——自解释靠结构而非文案。

**② 日节奏。** 采集 15 分钟一轮，但验证按天成熟（评分器按天跑、claim 按到期日结算），
决策频率是天和周。这不是秒级产品，不需要闪烁的红绿和实时推送。
推论：产品的心跳是**"自上次打开以来发生了什么"**，不是"此刻正在发生什么"。

**③ 主动词是"读"。** 用户的主要活动：读转录、读知识单元、读裁决、读联赛表、读研究档案。
写操作几乎不存在（唯一例外：实盘镜像录入）。
推论：**排版是第一 UI 材料**。层级靠字号、字重、留白组织，不靠框线和卡片。
知识页 2536a87 的重设计（放弃后台管理式布局，改为阅读优先）已经验证了这个方向，
本文将它从一个页面的选择升格为全产品原则。

**④ 机器自转。** collector / scorers / trader 三条进程自主运行，入库走 CLI，
提取走管线。前端不是这台机器的控制台。
推论：**界面作证，不操作**——展示机器做了什么（采集了什么、评了什么分、状态怎么变的），
带健康度和出处，而不是提供一排按钮。

**⑤ 诚实是产品身份。** 23 个假设全部 KILLED 照实入档；立项即写死预期
"首批联赛表大概率多数不显著"；含糊率和反技能名单与命中率同为产出。
推论：**为灰色设计**。一个为"庆祝胜利"设计的仪表盘，在诚实的数据面前会显得像坏了。
Fanisl 的界面必须在"样本小、不显著、不可验"是主流答案时，看起来**恰如其分**——
灰色的"未到期"与绿色的"✓"享有同等的排版尊严。

## 2. 用户心智模型：一条证据链，四种资产

四个核心资产不是四个并列的"板块"，它们是**同一条证据链的四段**：

```
Market Data ──作证──▶ Knowledge ──候选──▶ Research ──裁决──▶ Evidence（回写知识与档案）
（价格与指标的     （谁、何时、说了什么，   （方法进 harness、    （每个结论都能追问：
  时点正确基底）     被机械验证得如何）        setup 进评测台）      出处？口径？结果？）
```

Evidence 不是第四个页面，**Evidence 是全产品的组织原则**：其余三者的每一句话都必须
能被追问三次——

1. **出处？** → 逐字 quote、原文定位、发布时刻、原视频链接；
2. **口径？** → 提取时冻结的 ScoringSpec、success_def、基准价、预注册判据；
3. **结果？** → 机械评分、样本量、p 值、裁决记录。

**界面的根本承诺：这三问的答案永远在一跳之内。**

对象模型（用户脑中应有的实体）：

- 信源（creator）→ 内容（content，L0 不可变）→ 知识单元（claim / method / concept）
  → 评分（claim_scores）→ 规范节点（K5 归并后）→ 视图（联赛表、共识/冲突）
- 市场数据（metric 序列、daily_bars）作为证据基底被引用
- 研究档案（capstone、23 裁决、预注册）与评测台（playbook、实盘镜像、scorecard）作为纪律记录

四个**万能连接键**贯穿一切对象：**时间、标的、信源、主题**。任何两个对象只要共享
其中一个键，就应该可以互相到达。

一句话心智：**知识像代码一样被管理**（版本化、不可变历史、状态检查、可追溯），
**像文章一样被阅读**（单栏文档流、排版组织），**像实验一样被验证**（冻结口径、机械执行、
负结果入档）。

## 3. 七条设计原则

### 原则一：阅读优先——排版即界面

正文是主角，chrome 是仆人。单栏文档流是默认形态；表格只用于真正需要逐列比对的数据
（联赛表、scorecard、指标目录），不用作页面的默认容器。中文正文行高从容，数字一律
等宽表格数字。**为什么**：主动词是读（事实③）；且知识库要用十年，时尚的仪表盘三年就旧，
好的排版不会。

### 原则二：证据在一跳之内

任何呈现出来的判断——一个 ✓、一个命中率、一个 KILLED——点开或悬停即见其出处、口径、
样本。不允许出现无法下钻的结论数字。**为什么**：可验证是这个项目 23 杀锤炼出的独有能力，
是产品与"爬内容建库"的根本区别（事实⑤）；GitHub 的绿勾之所以可信，是因为它永远能展开成日志。

### 原则三：时间是第一维度

任何数字必须带 as-of；**发布时刻、到期时刻、评分时刻**三种时间永不混淆。列表默认按时间
组织（知识页按月分组已是正确做法）；claim 的一生（发布→等待→到期→裁决）应能在时间轴上
被看见。**为什么**：PIT 正确性是整个后端的第一戒律（pit.py、发布时刻冻结、评分阶梯），
前端若混淆"当时"与"现在"，等于在展示层重新引入未来函数。

### 原则四：密度服务判断，而非表演专业

密度分区，不均摊：

- **数据层（市场数据、联赛表、scorecard）**：密。表格、等宽数字、小字号、紧行距——
  这里用户在逐列比对。
- **知识层（内容流、阅读页、节点页）**：疏。~44rem 文档流、大留白——这里用户在理解。
- **判决层（评分徽标、状态戳）**：短。一个字符的语义（✓ ½ ✗ 未触发），不占一句话的位置。

**为什么**：Bloomberg 的密度成立是因为交易员按秒决策，密度=价值；Fanisl 用户按天决策，
照搬满屏四分格是 cosplay。按 Tufte 与 UI 密度分类学，追求的是**价值密度**
（单位时间和空间给读者的判断增量），不是视觉密度。

### 原则五：界面作证，机器运转

前端不做 CRUD 后台。采集状态、评分运行、入库记录以"发生了什么"的口吻呈现
（作证），不以"你可以操作什么"的口吻呈现（控制台）。唯一的写入口是实盘镜像录入——
它是刻意的、仪式性的（记录真实仓位），应当被设计成登记，而非表单堆。
**为什么**：事实④；界面上每多一个按钮，就多一个"这台机器需要人看着"的暗示，
而这台机器的设计目标恰恰是无人值守的幂等运转。

### 原则六：为灰色设计

视觉体系的默认状态是中性（未到期、样本小、不显著、D 级不可评），彩色是例外且仅表达
判决语义：绿=命中、红=落空、琥珀=部分/警示。禁止任何形式的成就化（徽章、连击、庆祝动效）。
p 值、样本量、"仅供跟踪"的注脚是界面的正式成员，不是免责声明小字。
**为什么**：事实⑤。预期管理已写死"多数不显著是结果不是失败"——界面必须让这个结果
看起来像深思熟虑的诚实，而不是产品的失败状态。

### 原则七：安静地积累十年

每个对象（内容、单元、节点、交易、假设）有稳定地址，可链接、可搜索、可引用。布局一旦
定型就保持稳定——专业工具的价值一半在于用户积累的肌肉记忆（Bloomberg 三十年不改语法，
Primer 强调 familiar patterns reduce relearning）。不追随视觉时尚，不做周期性改版。
**为什么**：核心资产是知识库本身——永久积累（设计文档第一句）。界面是这份资产的阅读器，
阅读器的美德是耐用。

## 4. 参考系研究：借什么，不借什么

| 参考 | 借 | 不借 |
|---|---|---|
| **Bloomberg Terminal** | 数字的严肃性（等宽、对齐、紧凑表格）；单窗口聚焦+命令直达（键盘寻址任何对象）；零延迟是体验的一部分 | 黑橙皮肤、四分格布局、实时闪烁；它的密度前提（秒级决策）在 Fanisl 不成立 |
| **GitHub** | 状态检查的语义（评分=CI 戳，可展开成日志）；不可变历史与版本对照的心智（L0/extractor_version 天然同构）；万物有 permalink | 协作机制（review/assign）；项目管理面 |
| **Notion** | 文档是原子阅读单元；低 chrome、排版组织信息 | 无限灵活的块编辑——Fanisl 的 schema 是冻结的，界面应显得**结构固定**，这是可信的一部分 |
| **Obsidian** | 引用跟随与反链（本地知识的连接方式）；本地优先、数据比应用长寿 | 图谱视图崇拜——设计文档已明确"先扁平库+标签+引用链，图状查询需求出现再升" |
| **TradingView** | 图表作为证据阅读器：claim 叠加在价格路径上（基准价→评估窗→判决）是最诚实的验证呈现 | 社交流、观点广场、发布者激励 |
| **Linear** | 速度即品质；键盘优先；有主见的默认值（少配置）；动效克制 | 任务/周期隐喻 |
| **Apple Health** | 系统被动采集，人只读周期性摘要与长期趋势；"记录"与"洞察"分层 | 圆环与激励——健康化的成就语言与"为灰色设计"直接冲突 |
| **Arc** | 敢于围绕真实的日常循环重排 chrome（而非沿用默认导航） | 为新奇而新奇 |
| **Apple HIG / Material / Primer / Atlassian** | 共同的底层：层级用少数通道一致编码；渐进披露；熟悉模式减少再学习；可及性从设计起点做 | 任何整套视觉语言的照搬——Fanisl 需要的是它们的**语法**，不是词汇 |

**信息密度高却不乱的产品，共享五个机制**（这是"专业感"的真正来源，与颜色字体无关）：

1. **严格的网格与对齐**——密度失控几乎总是对齐失控；
2. **层级只用少数通道、且用法恒定**——字重表强调、颜色表判决、字号表层级，从不互换；
3. **渐进披露**——密的是摘要层，细节按需展开（Bloomberg 藏复杂度，GitHub 展开检查日志）；
4. **单调是特性**——同类信息永远长同一个样子，识别取代阅读（recognition over recall）；
5. **快**——延迟是视觉秩序的一部分：快而密的界面比慢而空的界面更显安静。

**专业用户天天回来**，不是因为界面漂亮，而是因为：工具尊重他们积累的技能（布局稳定、
键盘可达）、数据是他们自己的、且每天打开都有真实增量。Fanisl 三条全占——设计只需不破坏。

## 5. 信息架构（模块层）

现状问题：顶栏 10 个平铺标签（对话 + 数据总览 + 6 个数据分类 + 交易评测 + 知识），
是数据平台时期的遗产——它把 6 个指标分类抬到与"知识"同级，把"对话"放在首位，
与"知识库是核心资产"的定位倒置。

新的层级：**四个空间 + 两个随处可用的工具**。

```
┌─ 今日 ────────── 前门：自上次打开以来的增量
├─ 知识库 ──────── 核心资产：内容流 / 阅读页 / 节点 / 联赛表 / 共识与冲突
├─ 市场数据 ────── 证据基底：目录 / 序列 / 覆盖（6 分类降为库内视图）
├─ 研究 ────────── 纪律档案：评测台（playbook/镜像/scorecard）+ 研究档案（capstone/裁决/预注册）
│
├─ 搜索 ────────── 工具：全局对象寻址（标的/信源/主题/任意文本），键盘直达
└─ 对话 ────────── 工具：随处可唤起的分析伙伴（从"主页"降级为"仪器"）
```

**各模块的一句话职责：**

- **今日**：回答"我离开的这段时间，机器学到了什么"——新入库内容、新到期评分、
  知识状态变化、系统健康。它是 K6 周报的日常化，是产品"持续"二字的落点。
- **知识库**：回答"关于 X，我积累了什么、可信度如何"。四种入口（时间流/信源/主题/标的）
  通向同一批对象；联赛表不是独立王国，是知识库按信源聚合的一个视图（设计文档原话）；
  阅读页保持已验证的单栏文档流形态。
- **市场数据**：回答"证据基底本身"。平时是仪表墙，被引用时是证人——从任何 claim 的
  基准价一跳到达对应序列。
- **研究**：回答"哪些方法经受住了纪律，哪些没有"。评测台是进行时（setup 评 edge、
  实盘镜像），研究档案是完成时（23 裁决永久陈列——负结果是资产，应被体面地展示而非埋藏）。
- **搜索**：万能连接键的具象化。标的、信源、标签是**枢纽对象**：搜"WTI"应同时给出
  相关 claim、价格序列、涉及它的 method 与研究假设。
- **对话**：Claude 是研究伙伴，不是首页。在任何上下文可唤起，带着当前对象的上下文提问。

**页面之间如何连接：引用跟随。** 导航的基本动作不是"切换板块"，而是**顺着脚注走**——
从单元到 quote 到原文；从评分到口径到价格序列；从 method 到 overlap_with_killed 到
研究日志的 H 条目;从信源联赛行到该信源全部 claim。四个连接键保证任何合理的追问
都有路径。这是 Obsidian 反链心智在结构化数据上的应用。

**用户的一天（叙事验证）：**

- **早晨（10-15 分钟）**：打开即"今日"——昨夜采集了 2 篇新内容、5 个 claim 到期
  （3✓ 2✗）、1 条知识从"新入"变为"已验证"。顺着感兴趣的评分下钻到阅读页，
  读完新内容的提取单元，扫一眼联赛表的变化。
- **交易时（分钟级、目标明确）**：查 playbook 里 setup 的当前状态；开仓后到研究空间
  做实盘镜像登记；需要盘面判断时唤起对话。
- **周末深研（小时级）**：按主题浏览知识节点，看跨源共识与冲突；翻研究档案里
  相关假设的裁决；让对话检索知识库回答"关于降息交易，信源们的分歧是什么"。

三种节奏、三种密度需求，正好对应原则四的密度分区。

## 6. 阅读体验的文法：结论—口径—证据

全产品共用一个**三行句式**，它已经在知识单元的排版中自发形成，应升格为普遍文法：

```
结论行   WTI ↓ 目标 62        ← 最大字号：这条知识说了什么 / 结果是什么
口径行   B · 至 2026-09-30 · 基准 68.4 · 对冲表述   ← 小、灰：怎么算的
证据行   │ "如果 OPEC 不增产，我认为油价会跌破…"    ← 引文块：凭什么
```

知识单元、claim 评分、交易记录（结果→参数→依据）、研究裁决（KILLED→判据→数据）
全部适用。读者训练一次，处处受益——这就是"单调是特性"。

配套约定（方向性，不进 token 细节）：

- 层级通道分工恒定：**字号=层级，字重=强调，颜色=判决，等宽=数据**；
- 一屏一个视觉重心；
- 色彩语义已定型且正确（中性灰基底 + 绿=命中 / 红=落空 / 琥珀=部分），不扩张；
- 中文为主的正文行高从容（现行 1.95 是对的），中西文混排时数字与符号用等宽字体；
- 空态说真话：指向产生数据的命令或机制（现有"用 backfill_transcripts 抓取…"是范本）。

---

## 7. 反模式（这个产品永远不做）

1. **KPI 大数字卡片墙**——没有观众，不需要给任何人留下印象；
2. **满屏红绿与实时闪烁**——日节奏产品不表演秒级紧张；
3. **成就化**——徽章、连击、庆祝动效，与"为灰色设计"直接冲突；
4. **管理后台式 CRUD 界面**——机器自转，界面作证；
5. **图谱可视化炫技**——扁平库+引用链已是明确决定，图状表示按需求升级；
6. **无法下钻的结论数字**——违反证据一跳原则的元素不得上线；
7. **营销化空态与解释性冗余**——唯一的读者不需要被推销；
8. **周期性视觉改版**——布局稳定性是对肌肉记忆的承诺。

## 8. 本文与 DESIGN.md 的关系

AI coding agent 参与开发时，逐次 prompt 描述设计必然漂移：每次生成各自解释"专业、简洁"，
积累出不一致的界面。解法是把设计决定沉淀为 repo 内的**可版本化文档**，让每次生成读同一部宪法
（awesome-design-md 所倡导的 DESIGN.md 模式；与本项目"提取规范冻结、评分器机械执行"
是同一个思想——**语义冻结在文档里，执行者只做机械遵循**）。

三层文档，本文是第一层：

1. **design-philosophy.md（本文）**——是什么、为谁、按什么原则。变更最慢。
2. **IA spec（下一步）**——空间/页面/对象的结构与连接、导航与寻址、每页的信息层级。
3. **DESIGN.md（再下一步）**——token（字号阶梯/间距/色彩语义）、组件清单、
   排版文法的具体规则、护栏（do/don't）。agent 实现界面时的直接依据。

任何页面设计若与本文冲突，先修宪，再动工。
