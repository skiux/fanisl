> **[已吸收/存档]** 本诊断催生了 [project-transformation.md](project-transformation.md)（范式转变蓝图）；其核心问题已由研究计划回答，见 [research-capstone.md](research-capstone.md)。

数据源：`data_export/server-2026-06-11/`。9 笔交易（8 平 1 挂单未成交）、20 条不交易记录、
47 次复评、约 4400 帧盯市快照。当时 `force_trade=true`、初始资金 $10,000。
样本期恰好覆盖 6/10 CPI 高影响日 + 当天午后的轧空反弹，整个样本都在「日线超卖 + 极端恐惧」单一市况里。

## 一、成绩单

| 指标 | 值 |
|---|---|
| 已平 / 胜率 | 8 笔 / 37.5% |
| 总盈亏 | -$202.15（-2.02%，约 2 天） |
| 期望 | -0.389R（95%CI ≈ [-0.85, +0.07]，n=8 不显著） |
| 盈利因子 / 最大回撤 | 0.27 / $224 |

| 手续费合计 | $37.27（≈ 平均单笔 $4.7，占平均盈利单的 19%） |

结构特征：
- **8 笔出场全部是 `thesis_invalidated`**——零止损触发、零止盈触发。计划盈亏比写的是 2.1~4.3，
  但实际从未有一笔走到 TP1；硬止损也从未被打到（都被 Claude 提前主动平了）。
- MFE（最大有利波动）：8 笔里只有 1 笔曾达到 +1.38R，其余 ≤0.91R；TP1 设在 0.94~2.81R。
  → **目标位在该市况下结构性不可达，planned RR 是纸面数字**。
- 方向 8 空 1 多，几乎全部押在「空头延续」上；置信度 54/54/54/54/54/56/56/61——**基本是常数，无校准信息量**。

## 二、分层归因：管理层在赚钱，进场层在亏钱

用导出的行情数据对 4 笔加密交易（#3 ZEC、#4 BTC、#6 ETH、#8 BTC）做反事实——
若不做任何管理、拿到原止损/止盈谁先到：**4 笔全部是止损先到（各 -1R）**。

| 口径 | 4 笔合计 |
|---|---|
| 实际（有管理） | -1.25R |
| 反事实（无管理） | -4.00R |
| **管理层贡献** | **+2.75R** |

即：提前识别论点失效并砍仓的能力是真实存在的（3 笔“盈利”全部是砍出来的小利润，而非到达目标）；
亏损的根源在**进场选择**——低置信度、逆挤压方向、事件日前进场。复盘的 skill_vs_luck 标注
（3 right_profit / 5 wrong_loss）与反事实证据一致，复盘层是诚实的。

## 三、已被数据证实的问题

### 交易判断侧
1. **强制交易污染了评测**：20 条 declines 全部提到 CPI、14 条提到超卖轧空风险——Claude 的
   自然判断是“这两天不该交易”，`force_trade` 把这些已识别为差的机会强行变成了交易
   （多笔复盘明说“若非强制交易模式应等待”）。结果既亏钱、又测不出真实选择力。
2. **方向集中 + 相关性无约束**：6/10 早晨 4 笔同向空单同时在场（BTC/ETH/ZEC/CRCL 高度相关），
   名义分散实为一注；6/10 13:44 的轧空对所有空单同时不利。
3. **CPI 当日开 5 笔空单**：自己 6/8-6/9 的 declines 反复以 CPI 为由拒绝交易，6/10 却在数据公布前
   集中进场——催化剂数据明明在库里，引擎没有事件封锁机制。
4. **TP 不现实**：目标距离没有用波动率/持有周期校验，2~4R 的 RR 在 MFE≤1.4R 的市况里是幻想。

### 工程/设计侧（已在当前代码中核实，改动不大所以仍然存在）
5. **手动 `open_trade` 绕过所有仓位约束**：最多 3 仓 / 总在险 ≤5% 只在 `scan()` 里检查，
   `service.open_trade()` 和 `engine.open_trade()` 都不查 → 实测出现 4 笔并发。
6. **`partial_exit` 语义错误**（trade #9 复现）：`apply_adjustment` 按
   `plan["computed"]["qty"] × reduce_pct`（**原始数量**）计算，Claude 表达的是“剩余仓位的 50%”，
   已减过一半后再减 50% = 100% 清仓。
7. **唤醒条件电平触发 → 复评风暴**：`time_elapsed_hours ≥ v` 与“逼近止损”带宽在条件持续满足时，
   每次 adjust 之后下一拍立即再次触发。2 天 8 笔 → 47 次 needs_review（28 次“逼近止损”、
   21 次“持仓≥1h”）、单笔最多 15 版计划；估算两天重决策 Claude 调用 80+ 次。复评结果 25/47 是 hold。
8. **限价挂单无 TTL**：#2 XAG 挂单永久滞留 `planned` 状态，无过期、无取消接口；
   留着隔夜/隔周成交就是按过时论点进场。
9. **软失效靠 LLM 回路执行，有延迟成本**：#7 计划失效位 81.05，实际经复评-决策-平仓链路
   成交在 81.26，亏损 -1.18R 超过计划的 -1R。失效价是结构化数字，本可由引擎确定性执行。
10. **评测度量缺口**：scorecard 没有置信度校准、没有 MFE/MAE、没有基准对照
    （随机进场/不管理 buy-the-plan）、declines 的 watch_for 无人验证——“何时不交易”这一半判断力
    完全没有被评分。

## 四、改进路线（按杠杆排序）

1. **撤掉全局强制交易，改成评测设计**：force 仅作为单独实验账户（A/B：自然 vs 强制），
   或改“每周最少 N 笔”软约束。主账户恢复 Claude 的拒绝权，同时把 declines 纳入评分（见 4）。
2. **把确定性约束全部下沉到引擎**（Claude 提议、引擎裁决）：
   - `open_trade` 统一走容量检查：仓位数、总在险、**同向净敞口/相关组上限**；
   - 事件封锁：开仓前查 `catalyst_items`，高影响事件前 X 小时拒绝/降风险（数据已在库里）；
   - 计划校验追加“TP 可达性”：TP1 距离 ≤ k×ATR(交易周期×预期持有)，否则拒绝或标记；
   - 失效价作为结构化字段由引擎执行（第二止损），不再等复评回路；
   - 挂单 TTL + 取消接口。
3. **治理复评风暴**：唤醒条件改边沿触发 + 冷却期（每条件命中一次、adjust 后 30min 内不重触发）；
   “逼近止损”加去抖。预期把复评调用砍掉 60%+，同时减少“反复 hold”的噪声决策。
4. **补齐评测度量**：每笔落库 MFE/MAE 与出场效率（realized/MFE）；平仓后自动跑
   “不管理反事实”（原 SL/TP 先到谁）入库 → 管理层贡献可持续追踪；置信度分桶校准曲线；
   declines 的 watch_for 到期自动用行情验证对错。这样进场力/管理力/拒绝力三层各自有分数。
5. **修 `partial_exit` 基数**：reduce_pct 明确定义为“剩余仓位百分比”，engine 按 `tr["qty"]` 计算，
   schema 描述同步改。
6. **样本量与市况覆盖**：n=8 的期望 R 置信区间横跨 0，当前一切结论都只对“超卖恐慌市”成立。
   降低单笔风险、提高笔数、跨市况积累，评测才有统计效力。

## 五、对“管理层是真 alpha”保持怀疑的理由

管理层 +2.75R 的归因只有 4 笔可验证样本，且全部发生在同一场反弹里；
“总是提前砍”在趋势延续市里会系统性砍飞利润（#6 ETH 的 MFE 1.38R 最终只拿到 0.24R 已是苗头）。
出场效率（realized/MFE）当前均值仅 ≈0.4，需要在更多市况下观察这是“风控”还是“胆小”。
