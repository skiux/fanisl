# 会话闸门（知识引擎前端）

后端 2026-09-02 起全站要求登录，这一层是它在前端的另一半。

```
main.tsx
└── AuthGate            ← 没登录就只渲染登录页，应用本体一行都不挂载
    └── Root            ← 路由与全部页面
```

| 文件 | 职责 |
|---|---|
| `session.ts` | 会话状态（可订阅的极小 store）+ `login` / `logout` / `refreshSession` |
| `AuthGate.tsx` | 闸门：挂载时问一次 `/auth/me`，并接管全局 401 |
| `LoginPage.tsx` | 登录页 |
| `auth.css` | 沿用全站纸面语言（`--paper` / `--ink` / `--sage`），不另起一套视觉 |

## 几个不是随手定的决定

**闸门在最外层，不是"渲染应用再各处判断"。** 后者要求每个页面自己处理未登录，
漏一个就是一屏报错。闸门默认关，与后端那道中间件同一个方向。

**登录态只能问后端。** 会话 cookie 是 `HttpOnly` 的，JS 读不到。不要在 localStorage
里镜像一份登录态——那份镜像与真实会话没有任何强制关系，过期之后界面显示成已登录、
每个请求却都 401。

**`credentials: 'include'`。** 线上同源时浏览器默认就带 cookie，但本机开发是跨端口的
（页面 5173 / API 8000），默认的 `same-origin` 会把 cookie 丢掉——表现是"登录成功了
但每个请求还是 401"。写成 include 两种情形都对。

**全局 401 排除 `/auth/*`。** 登录时口令输错也是 401，那是表单内的错误，
不该触发一次"全局登出"——否则输错一次，登录页会把自己重置一遍。

**不区分"用户名不存在"和"口令错误"。** 后端两种情况返回同一句话、耗时也一致；
前端要是自作聪明拆开显示，就把后端特意堵上的用户名枚举信道又打开了。

**退出失败不假装成功。** 退出请求失败时服务端会话其实还活着。`logout()` 清本地状态
但**把错误抛出去**，顶栏接住之后刷新页面重新问 `/auth/me`——让服务器说真话，
而不是由前端猜。

**登录后停在原来那一页。** 闸门只换渲染的内容，地址栏的 hash 从头到尾不动。

**账号菜单里的「账号」和「用户管理」去的是资产台**（`/console/#/account`、
`/console/#/admin`）——两个应用共用一套账号，账号相关的界面只做一份。
导航行里的「资产」用一条竖线与研究工具分开：它是整行里唯一一个离开本应用的入口，
混在工具组里读着像本应用的第八页。

## 鉴权关闭时

后端 `AUTH_ENABLED=false` 时 `/auth/me` 返回一个占位用户（`display_name: "鉴权已关闭"`），
顶栏上一眼能看出这不是真登录。**开关是整套生效的**：只放行中间件而让 `/auth/me` 继续
401 的话，前端会卡在登录页——而关掉鉴权的本意正是不需要登录。

## 测试

- `session.test.ts`（vitest）：状态迁移、401 分流、`credentials: 'include'`、
  退出失败的处理。
- `client.test.ts`：非 JSON 的错误响应要指到 nginx，而不是原样丢一句上游的
  `Not Allowed`（线上真踩过，害人以为自己记错了口令）。
- `e2e/auth.spec.ts`（Playwright，桌面与移动两个视口）：未登录只渲染登录页、口令错误、
  被限速、登录后停在原页、会话中途失效整体切回、顶栏退出。
- 原有 e2e 用例经 `mockAuth` 默认注入一个已登录用户，验的仍是它们本来要验的东西。

真后端 + 真 cookie 的端到端在 2026-09-02 手工验过一遍（错误口令 → 提示且清空口令、
正确口令 → 落回 `#/knowledge`、顶栏显示用户名）。
