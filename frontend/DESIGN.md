## 0. 使用方式

1. 实现任何界面前先读本文；本文没写的，从 Design Rules（§18）推导；推导不出的，
   属于规范缺口——补充本文后再实现，不做一次性的临时决定。
2. 三个全局刻度盘为本项目**锁死**（覆盖任何通用前端技能的默认值）：
   - `DESIGN_VARIANCE = 3`（可预测、对齐、稳定——布局是十年仪器，不是作品集）
   - `MOTION_INTENSITY = 2`（仅状态反馈动效；无入场编排、无常驻动画）
   - `VISUAL_DENSITY = 分区`（数据层 7 / 知识层 3 / 判决层：单字符，见 §6）
3. 设计语言的融合公式（六个来源各取其**语法**，不取皮肤）：

| Bloomberg | 数字的严肃性；数据层的密度；单屏聚焦 | §6 Density、§7 表格 |

## 1. 颜色哲学

**一句话：中性灰承载一切内容，彩色只说一件事——判决。**

1. **灰阶只用 zinc 一族**。禁止混入 gray/slate/stone（冷暖漂移）。页面底色统一
   `zinc-50`（现存 `#f9fafb` 属 gray 族，迁移时改正）。
2. **彩色是语义，不是装饰**。绿/红/琥珀只表达两类语义，且二者**不在同一视觉组内混用**：
   - 知识层：**判决**（命中/落空/部分）；
   - 数据层：**涨跌**（价格变动方向）。
   若判决与价格出现在同一组件内（如 Claim 卡内嵌价格），价格退为中性色 + 符号（`+/−`），
   彩色让位给判决。
3. **强调色 emerald-600 唯一**，仅用于：品牌标识、主要动作按钮、focus ring、图表主序列。
   饱和度不再提高，禁止渐变。
4. **无纯黑纯白依赖对比**：正文最深 `zinc-900 #18181b`；禁止 `#000`。
5. **浅色主题是正典**。阅读优先决定了纸面感；暗色主题暂不做，禁止做一半
   （tailwind `darkMode: 'class'` 保留但不启用）。
6. 彩色出现频率是被设计的：**一屏之内彩色元素应当稀少**——灰是常态（未到期、
   不显著、D 级），这是"为灰色设计"的字面执行。

### 1.1 色彩 Token（唯一来源，实现时映射进 tailwind.config）

| Token | 值 | 用途 |
|---|---|---|
| `bg/page` | `#fafafa` zinc-50 | 页面底 |

| `ink/secondary` | `#52525b` zinc-600 | 次级正文、表格数据 |
| `ink/meta` | `#a1a1aa` zinc-400 | 元数据、口径行、注脚、未激活导航 |
| `ink/faint` | `#d4d4d8` zinc-300 | 定位符、禁用、最弱注记 |
| `border/default` | `#e4e4e7` zinc-200 | 分隔线、引文竖线、表格行线 |

死掉的假设是档案不是警报。

## 2. Typography

**层级=字号，强调=字重，判决=颜色，数据=等宽。四通道分工恒定，禁止互换。**

字体：`Geist Sans`（UI 与正文）+ `Geist Mono`（一切数据态文本）。中文回退
`system-ui`（PingFang SC / Microsoft YaHei）。禁止引入第三字体、禁止衬线、禁止斜体
（中文无斜体传统，强调用字重或 `ink/primary`）。

### 2.1 字号阶梯（唯一合法集合，px）

| Token | px | 行高 | 用途 |
|---|---|---|---|
| `type/2xs` | 11 | 1.4 | 大写小标签（tracking 0.14em）、徽标内文、locator、上标注记 |
| `type/xs` | 12 | 1.5 | 元数据行、口径行、注脚、侧栏正文、表头 |
| `type/sm` | 13 | 1.5 | UI 标准：导航、按钮、表格单元格、次级列表 |
| `type/base` | 14 | 1.6 | UI 正文块、说明段落 |
| `type/md` | 15 | 1.9(正文)/1.5(UI) | **阅读正文**（转录、规则）、单元结论行、列表条目标题 |
| `type/lg` | 17 | 1.5 | 详情页小节标题、重要数字的展示 |
| `type/xl` | 20 | 1.4 | 区块标题、次级页面标题 |
| `type/2xl` | 24 | 1.3 | 页面标题（一屏至多一个，tracking-tight） |

- 禁止阶梯外字号（现存 13.5/14.5/15.5/23/26 迁移时就近归位）。
- 页面标题不超过 24px——层级靠对比与留白，不靠尺寸嘶吼。
- 字重只用 400 / 500 / 600。600 仅限页面标题与结论行；正文强调用 500。
- 全部数字 `tabular-nums`；**凡表达数据的文本一律 Geist Mono**：价格、比率、p 值、
  时间戳、locator、符号代码（BTC/USDT）、评分徽标。判断标准：这个文本会被逐位比对吗？
  会→mono。
- 中文正文（≥3 行的连续阅读）行高 1.9、栏宽 ≤ 44rem；中西文与数字之间保留半角空格
  （"目标 75"、"42% 命中"）。
- 大写小标签（英文/拼音场景）统一：11px / 500 / `tracking-[0.14em]` / `ink/meta`。

## 3. Spacing

4px 基数，唯一合法阶梯：**4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96**（px）。

节奏规则（决定用哪一档，不靠感觉）：

| 关系 | 间距 |
|---|---|
| 同一行内的相邻元素（徽标与文字） | 4–8 |
| 一个对象内部的行与行（结论行→口径行→引文） | 8–12 |
| 同组对象之间（列表里两个单元） | 24–36（阅读流取大，表格取行高） |
| 组与标题之间 | 12–16 |
| 区块（section）之间 | 48–64 |
| 页面顶部留白 | 40–48 |
| 页面左右内边距 | 24（`px-6`），窄屏 16 |

原则：**间距表达从属关系**——两个元素的距离与它们的语义距离成正比。禁止用边框弥补
间距失序。

## 4. Grid

不用营销式 12 栏栅格。页面只有三种容器，按内容性质选择：

| 容器 | 宽度 | 用途 |
|---|---|---|
| **Reading** | `max-w-[44rem]` 单栏居中 | 阅读页（内容详情、节点页、研究档案文档） |
| **Ledger** | `max-w-[68rem]`，主栏 `minmax(0,44rem)` + 右侧 `13rem` 淡化侧栏（xl 以下侧栏隐藏） | 列表流+情境侧栏（知识库首页、今日） |
| **Instrument** | `max-w-[96rem]` 流式，内部 CSS Grid 分区 | 数据密集页（市场数据、scorecard、联赛表全览） |

- 布局用 CSS Grid（`grid-cols-*` + `gap`），禁止 flex 百分比算术（`w-[calc(33%-1rem)]`）。
- 全页骨架保持现状：body 不滚，header 固定，滚动只发生在内容区（`PageShell` 模式）。
- 侧栏永远是**注脚地位**：`type/xs`、`ink/meta`、sticky，宽度不超过 13rem；
  主栏内容在无侧栏时必须自足。
- < 768px 一律塌缩为单栏 `w-full px-4`，无水平滚动（表格例外：容器内 `overflow-x-auto`）。

## 5. Card 与 Panel

**默认无卡片。** 结构靠留白、字号与分隔线表达（Obsidian/Apple 语法）。盒子是稀缺资源，
用在真正需要"这是一个独立物件"的地方。

### 5.1 三级容器（从轻到重，优先用轻的）

| 级 | 形态 | 用途 |
|---|---|---|
| **Block** | 无边框无底色，仅留白分组；悬停时 `bg/hover` 圆角 12px（`-mx-4 px-4` 负边距扩展命中区） | 阅读流中的一切对象：知识单元、内容条目、交易记录行 |
| **Panel** | `bg/surface` + 1px `border/default` + 圆角 12px + 内边距 16–24；**无阴影** | Instrument 容器里的仪表分区（图表、表格、计分卡）；表单区 |
| **Overlay** | Panel + `shadow-lg`（唯一允许阴影处），阴影带 zinc 色调 | 下拉、命令面板、对话框 |

### 5.2 硬规则

- Panel 不嵌套 Panel；Block 不加边框。盒中盒 = 设计失败，回去改层级。
- 阴影只属于 Overlay 层（有真实 z 轴遮挡时）。平面内容禁止阴影和"悬浮卡"。
- 圆角阶梯：4（徽标）/ 8（按钮、输入框）/ 12（Panel、行悬停、Overlay）。
- 禁止三等分卡片横排、禁止 KPI 大数字卡片墙。统计数字用**文字行**呈现
  （"135 判断 · 60 已到期 · 命中 42%"），不用一人一盒。

### 5.3 表格（数据层的 Panel 内形态）

- 表头：`type/xs` / 500 / `ink/meta`，无底色，底边 1px `border/default`。
- 行：高 36–40px，行线 1px `border/subtle`，悬停 `bg/hover`；禁止斑马纹。
- 数字列右对齐 + mono；文本列左对齐；禁止居中对齐数据。
- 单元格内边距：`px-3 py-2`。
- 比率/统计列必须带样本量（见 §12）。

## 6. Density

密度分区是本产品的结构特征，按**读者当下的任务**给密度：

| 区 | 密度 | 排版参数 |
|---|---|---|
| **知识层**（内容流、阅读页、节点页） | 疏（3/10） | 44rem 单栏；对象间距 24–36；正文 15px/1.9；一屏 6–10 个对象 |
| **数据层**（联赛表、scorecard、指标表、序列图） | 密（7/10） | 行高 36–40px；13px mono 数字；分隔线代替留白；一屏 20–40 行 |
| **判决层**（徽标、状态戳） | 极密（单字符语义） | ✓ ½ ✗ + 2–4 字中文态；11px mono 徽标，寄生在其他层的行内 |

规则：

- 一个页面可以同时含多个密度区，但**一个视觉组内密度必须均匀**。
- 密度靠删减和对齐达成，不靠缩小字号：低于 11px 的文本禁止存在。
- 数据层禁止在单元格里写句子；知识层禁止把句子塞进表格。内容性质决定它去哪个区。
- 空间富余不是提高密度的理由：知识层留白是功能（阅读节奏），不是浪费。

## 7. Timeline（时间的呈现）

时间是第一维度（哲学原则三），呈现规范：

1. **列表默认按时间倒序，按月分组**。月标题用大写小标签样式（"2026 年 7 月"，
   11px/0.14em/`ink/meta`）。
2. **三种时刻永不混淆**，各有固定措辞与位置：
   - 发布时刻：对象元数据行（"7 月 16 日"）；
   - 到期/评估时刻：口径行（"至 2026-09-30"，mono）；
   - 评分时刻：徽标 title 与评分详情内。
3. **日期格式**：正文语境 `7 月 16 日`（跨年补 `2026 年`）；数据语境 ISO `2026-09-30`
   （mono）；徽标内 `MM-DD`（mono）。
4. **相对时间只作辅助**（"今天/昨天"仅限今日流），任何证据语境必须给绝对时刻；
   悬停 title 永远含完整时间戳。禁止"3 天前"式模糊表述出现在知识与验证对象上。
5. **任何数字必带 as-of**：图表右上角、快照数值旁、联赛表脚注，格式
   `截至 2026-07-17`（`type/xs`、`ink/meta`）。
6. **Claim 生命线**（时间轴组件的语义）：发布 ● → 等待（灰线）→ 各评估时点 ○
   （到期后按判决着色）→ 最终态。水平呈现，宽度映射时长；未到期部分虚线。
   这是 claim 详情与今日流的标准时间图元，用 SVG/纯 CSS 实现，无动画。

## 8. 图表（TradingView 语法，recharts 实现）

- 图表是**证据阅读器**，不是装饰：每张图回答一个明确问题，标题写成那个问题的答案
  （"WTI 自发布日 −8.2%"），不写"价格走势"。
- 线色顺序：主序列 `zinc-700`；基准/对照 `zinc-400` 虚线；强调/当前 `accent`；
  多序列续用 cyan-600、amber-600（超过 4 条 = 该拆图）。
- 面积填充禁止；渐变禁止；网格线 `border/subtle` 仅横向；轴文字 11px mono `ink/meta`。
- **判决叠加**（claim 证据图的标准形态）：基准价水平虚线 + 目标价水平线 +
  评估时点竖线，判决点用 verdict 色圆点。价格线本身保持中性。
- tooltip：Overlay 样式（§5.1），mono 数字，含完整时间戳。
- 无入场动画（recharts `isAnimationActive={false}` 一律关闭）。
- 迷你图（sparkline，行内 80–120px 宽）：单线 zinc-400、无轴无网格，仅示形状；
  涨跌色只用于末值数字，不用于线。

## 9. Knowledge Card（知识对象的通用文法）

一切知识对象（claim / method / concept，及评分、交易、裁决）共用**三行文法**，
以 Block 形态（§5.1）存在于阅读流中：

```
┌ 结论行  type/md 15px · 500 · ink/primary        ← 这条知识说什么（+行内判决徽标）
├ 口径行  type/xs 12px · 400 · ink/meta           ← 等级 · 期限 · 基准 · 措辞（· 分隔）
├ 引文块  border-l-2 border/default · pl-14px      ← 逐字 quote（凭什么），13px · ink/secondary
└ 扩展区  （按类型：条件/规则/评分口径）12–13px      ← 可选，见各类型
```

- 行间距：结论→口径 4px；口径→引文 10px；引文→扩展 8px。对象之间 36px。
- 结论行是唯一的 `ink/primary`；一个对象内只有一处视觉重心。
- 徽标寄生在结论行行内（baseline 对齐，`gap-2.5`），不另起一行。
- 元数据用 `·` 间隔符连接（两侧空格），不用竖线不用逗号。
- 整个 Block 可点击进入详情（悬停 `bg/hover`），但引文内的链接、徽标各自可独立点击。

### 9.1 Claim Card

结论行构造（字段→文字的机械映射，现 `claimHeadline` 逻辑升级为规范）：

```
{asset_symbol ?? asset_text} {direction 符号} {magnitude 表述}
方向符号：up ↑ · down ↓ · flat → · range ↔ · vol_up σ↑ · vol_down σ↓
magnitude：target→"目标 75" · low+high→"62 ~ 75" · 仅 low→"守 62" · 仅 high→"压 75"
符号与数字用 mono。
```

口径行字段序（存在才显示）：
`验证等级字母(mono·等级色) · 至 {最后评估日} · 基准 {ref_price}(mono) · {措辞态}`
措辞态仅在非 explicit 时显示："对冲表述" / "试探表述"。

扩展区（按需，`type/xs` `ink/meta`）：
- `前置条件：{condition_text}`，不可机械判定时追加 `（不可机械判定）`；
- `评分口径：{success_def}`。

评分徽标（行内，可多个=多时点）：`MM-DD ✓` 格式，11px mono，soft 底 + verdict 色字，
`rounded px-1.5`；title 含 `{horizon_label} · {outcome} · 评估价 {eval_close}`。
未到期时点显示 `MM-DD ○`（`verdict/neutral`）。

### 9.2 Method Card

- 结论行：`{name}`。
- 口径行：`{family 中文} · 可测性 {A/B/C} · {summary}`；
  若 `overlap_with_killed` 非空，追加 `与 {H编号} 重叠`——并链接到研究日志对应条目
  （证据一跳）。
- 扩展区：`rules` 用圆点列表（13px / `ink/body` / 行距 8px），保留原始表述；
  `claimed_performance` 若展示必须带前缀 **"自称："**（记录不采信的排版化）。

### 9.3 Concept Card

- 结论行：`{canonical_statement}`；stance=reject 时前缀 `反对：`。
- 口径行：`{category 中文}`；有 `regime_qualifier` 时追加 ` · {qualifier}`。
- 无判决徽标（concept 不评分）；共识/争议度（K6 后）以 `n 源一致 / n 源冲突` 文字入口径行，
  冲突时链接到冲突对照。

### 9.4 中文术语表（界面用词唯一来源）

| 数据词 | 界面词 |
|---|---|
| claim / method / concept | 判断 / 方法 / 认知 |
| creator | 信源 |
| content | 内容（按平台可作"视频/文章"） |
| verifiability A–D | 等级 A–D |
| scoreboard | 信源战绩（联赛表） |
| hit / partial / miss | ✓ / ½ / ✗（文字语境：命中/部分/落空） |
| condition_not_met / condition_unverifiable / unpriceable | 未触发 / 不可验 / 无价格 |
| pending（未到期） | 未到期 |
| stance hedged / speculative | 对冲表述 / 试探表述 |

## 10. Panel 型对象：验证与交易的表格形态

知识对象进入数据层（联赛表、scorecard、评分明细）时改用表格行形态，同一对象的
两种形态字段一致、措辞一致——读者在两个密度区之间切换时不需要重新学习。

---

## 11. Timeline 型对象：今日流（增量条目文法）

今日流条目 = 时间戳 + 事件句 + 证据链入口，单行起排：

```
07-17  5 个判断到期评分：3✓ 2✗ ── Andy Lee 财经        ← mono 时间戳 · 事件句 · 归属
```

- 事件句是完整中文句，动词用"作证口吻"：入库、到期、评分、状态变化、采集；
- 判决数字内联徽标语法（3✓ 绿、2✗ 红）；
- 每条可点击展开为对应的 Knowledge Card 列表或跳转详情；
- 无未读红点、无计数徽章轰炸——增量本身按时间分组呈现即可。

---

## 12. Verification（验证的呈现纪律）

验证是产品的身份，呈现有硬规则：

1. **比率永不裸奔**：任何命中率/含糊率必须同视觉组内带样本量。
   格式：`命中率 42% (25)` 或 `已到期 60/103`。
2. **显著性如实**：sign 类给单侧二项 p（`p 0.21↓`，mono；↑/↓=方向侧），
   其余类型 v1 无基线——**不显示就是不显示**，禁止编造可比性。
3. **小样本免责是正式成员**：聚合统计的视觉组底部固定注脚
   （`type/xs` `ink/meta`）："评分为到期机械执行（hit=1，partial=0.5）。样本仍小，仅供跟踪。"
4. **判决徽标是戳，不是奖章**：无动效、无渐变、无发光；落空与命中同尺寸同字重。
5. **灰是主角**：未到期/未触发/不可验/无价格四态用 `verdict/neutral`，与彩色判决
   同等排版；一屏全灰是合法且常见的状态，界面不得因此显得"空"或"坏"。
6. **联赛表是知识库的视图**：呈现为知识库内的一个区（侧栏或独立密度区），
   不做成独立"排行榜产品"；行点击进入该信源的全部判断（证据一跳）。
7. 评分徽标 title 必含：时点、判决、评估价。点击进入评分详情（含冻结口径全文
   与证据图 §8）。

---

## 13. Evidence（证据的呈现纪律）

1. **引文块规范**：左竖线 2px `border/default`、缩进 14px、13px `ink/secondary`、
   行高 1.7；quote 逐字呈现**禁止编辑压缩**；超过 4 行折叠（尾部"展开 ›"），
   折叠不截断句子中间。
2. **locator 前缀**：mono 11px `ink/faint`，视频时间点（`12:34`）或字符偏移，
   置于引文块行首。
3. **出处链**（证据一跳的实现语法）：引文块 → 内容详情（定位到该段）→ 原视频/原文
   外链（`ArrowSquareOut` 13px 图标后缀）。链条每一跳都是显式可点击的。
4. **口径可及**：任何判决元素 hover 即见口径摘要（title/tooltip），click 即达口径全文。
   禁止出现"无法下钻的结论"（哲学原则二的执行点）。
5. **正文内链接**：下划线 `decoration-1 decoration-zinc-300`，悬停 `decoration-zinc-500`；
   颜色随正文不变蓝——链接是脚注不是按钮。UI 导航链接（非正文）用颜色变化不用下划线。
6. **引用跟随的方向感**：向下=出处（quote→原文），向外=语境（标的→序列、信源→战绩、
   标签→同主题）。两类入口在排版上分开：出处在引文块内，语境在口径行的可点击字段上。

## 14. Animation

**动效只做一件事：确认状态变化。** 不叙事、不装饰、不常驻。

| Token | 值 | 用途 |
|---|---|---|
| `motion/instant` | 100ms linear | 颜色/透明度的悬停反馈 |
| `motion/quick` | 150ms `cubic-bezier(0.16,1,0.3,1)` | 按钮按压、徽标出现 |
| `motion/expand` | 200ms 同上 | 折叠展开、Overlay 出现（fade+2px 位移） |

- 只动 `transform` 与 `opacity`；禁止动 width/height/top/left。
- 按压反馈：`active:translate-y-px`（现约定保留）。
- **禁止**：页面/列表入场动画、stagger 瀑布、骨架 shimmer 扫光（加载态用纯 opacity
  脉动 ≤1.5s 周期）、视差、常驻循环动画、spring 物理库、滚动触发编排。
- 数据刷新（60s 轮询）**静默替换**，不闪烁不高亮；新增条目不做进场动画——
  这是一台安静的机器。
- `prefers-reduced-motion` 时全部动效退化为瞬时切换。

## 15. Interaction

1. **悬停**：可点击的 Block/行 → `bg/hover`；可点击的文字 → `ink/meta`→`ink/primary`
   的颜色迁移（150ms）。悬停永远只揭示，不移动布局（禁止 hover 时出现占位变化）。
2. **Focus**：键盘可达是硬要求。`focus-visible:ring-2 ring-accent ring-offset-2`，
   禁止 `outline-none` 裸奔。
3. **键盘**：`⌘K` 保留给全局搜索（对象寻址）；`Esc` 关闭 Overlay/返回上级；
   方向键在表格/列表中移动（实现可后置，快捷键位现在冻结）。
4. **点击目标**：交互元件 ≥32×32px 命中区（文字链接豁免）；行级点击用负边距扩展
   （`-mx-4 px-4`）而非撑大内容。
5. **cursor**：`pointer` 只出现在真正可点击处；禁止装饰性 pointer。
6. **状态四件套**（每个取数视图必须实现，缺一不上线）：
   - **Loading**：与真实布局同构的骨架（灰块 opacity 脉动），禁止转圈 spinner；
   - **Empty**：真话空态——说明数据从哪来 + 产生数据的命令
     （范本："还没有内容。用 backfill_transcripts 抓取信源的近期视频。"），
     `type/base` `ink/meta`，无插画无营销；
   - **Error**：行内呈现，`verdict/miss` 色小字 + 具体错误 + 重试链接；不用 toast；
   - **Stale**：数据超龄时在 as-of 处标注（"截至 07-15（已 2 天未更新）"，amber）。
7. **写操作只有一处**（实盘镜像录入）：表单 label 在输入框上方、`gap-2`、helper 与
   error 在下方；提交按钮 `accent` 底白字，是全站唯一的实心彩色按钮。
8. **确认与破坏**：删除类操作（对话删除）行内二段确认（"确认删除？"文字态），
   不弹模态；知识与验证数据在界面上**没有删除入口**（L0 不可变的界面化）。

---

## 16. 数字与文案格式

- 价格：沿用标的惯例小数位（BTC 整数、油品 2 位），千分位分隔，mono。
- 百分比：整数位为默认（`42%`）；p 值两位小数（`0.21`）；R 值两位小数带符号（`+1.30R`）。
- 涨跌：数据层 `+2.4%` 绿 / `−1.8%` 红（真负号 `−` 非连字符）；知识层内价格变动
  一律中性色 + 符号。
- 大数：`15.7 万字`、`247 单元`——中文计数单位，不用 K/M。
- 界面文案是**作证口吻**：陈述已发生的事实（"已到期 60"、"采集于 07-17 03:00"），
  不用祈使营销语；无感叹号；无 emoji（图标一律 Phosphor，尺寸 13–16px，
  正文语境 regular 字重、小尺寸导航 bold）。
- 术语用 §9.4 术语表，同一概念全站同词。

## 17. Do / Don't 速查

| Do | Don't |
|---|---|
| 留白与字号分层，Block 无框 | 卡片套卡片、KPI 卡片墙、三等分横排 |
| 彩色=判决/涨跌，一屏彩色稀少 | 装饰性彩色、渐变、发光、AI 紫 |
| 数字 mono+tabular，右对齐，带 as-of | 无出处数字、居中对齐数据、相对时间当证据 |
| 比率带样本量，p 值如实，灰态体面 | 裸奔的命中率、编造基线、庆祝动效 |
| 骨架加载、真话空态、行内错误 | 转圈 spinner、营销空态、toast 轰炸 |
| 150ms 状态反馈，静默刷新 | 入场编排、常驻动画、shimmer、视差 |
| 三行文法（结论—口径—证据）处处同构 | 每页发明新排版、同义异词 |
| 表格用于逐列比对，行线分隔 | 表格当页面容器、斑马纹、句子进单元格 |
| 稳定布局与稳定地址 | 周期性改版、悬停引起布局跳动 |
| Geist 双字体 + 阶梯内字号 | 引入新字体、阶梯外字号、<11px 文本、斜体中文 |

## 18. Design Rules（编号硬规则，review 时逐条可查）

- **R1** 任何呈现的数字带 as-of（本体、title 或同组注脚三者之一）。
- **R2** 任何比率与统计量同视觉组内带样本量。
- **R3** 任何判决元素可下钻至口径与出处（hover 摘要 + click 全文）。
- **R4** 彩色只表达判决或涨跌；同一视觉组内二者不并存；装饰性彩色为零。
- **R5** 一屏至多一个 24px 标题、一个视觉重心。
- **R6** 容器至多一层边框：Panel 不嵌套，Block 无边框，阴影仅 Overlay。
- **R7** 字号只取 §2.1 阶梯；数据态文本一律 mono+tabular。
- **R8** 间距只取 §3 阶梯，且反映语义距离。
- **R9** 发布/到期/评分三种时刻在措辞与位置上可区分，证据语境用绝对时间。
- **R10** 动效仅 transform/opacity、≤200ms、只确认状态变化；无常驻动画。
- **R11** 每个取数视图实现 loading/empty/error/stale 四态方可合入。
- **R12** 知识对象遵循三行文法；同一对象在阅读流与表格两形态字段与措辞一致。
- **R13** 界面无删除/编辑知识与验证数据的入口；唯一写操作是实盘镜像录入。
- **R14** 灰是默认态：未到期/不可验/不显著必须与彩色判决同等排版尊严。
- **R15** 术语用 §9.4 表，全站同词；文案作证口吻，无 emoji、无感叹号。
- **R16** 不引入新依赖、新字体、新颜色族；规范缺口先补文档再实现。
